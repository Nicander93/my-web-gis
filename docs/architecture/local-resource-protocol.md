# 本地场景资源协议

M6 的第一层由原生的 `webgis-resource` 协议实现。它按受控目录读取原文件，既不复制大型模型，也不把根 JSON 改成会丢失 base URL 的 Blob。项目引用模型、保存路径重算和重定位界面会在下一层接入，所以本文不代表 M6 已整体完成。

## 宿主接口

- `grant_local_resource_directory(directory)` 返回随机 key、目录的 base URL 和真实目录。宿主只能为已授权的项目目录或用户选择的目录调用，不能根据任意项目内容自动授权外部路径。
- Windows 上的 base URL 是 `http://webgis-resource.localhost/<key>/`。路径保留目录层次，子瓦片、GLTF buffer、纹理和嵌套 JSON 都能按标准 URL 规则解析；Unicode 文件名按 URL 编码传输。
- key 用系统随机数生成，最多同时存在 256 个有效授权。`revoke_local_resource_directory(key)` 释放指定授权后，旧 URL 不再能读取文件。URL 和 key 属于运行时能力，不应写进正式项目或恢复草稿。
- 请求只支持 GET、HEAD、OPTIONS，来源限制在当前 Tauri 页面的 origin。每次请求都会 canonicalize 文件路径，拒绝目录遍历、编码后的分隔符、NTFS ADS、越过授权目录的符号链接或 junction、未授权的 token 以及目录请求。
- 文件 IO 在 Tauri 的 blocking runtime 中执行。单次响应最多 512 MiB，更大的文件可以通过范围读取取得较小的片段。大规模目录和 GPU 性能尚未验收。

## HTTP 与文件行为

- 按扩展名返回 JSON、GLTF、GLB、PNG/JPEG/WebP、KTX 等 MIME 类型，其它二进制类型返回 `application/octet-stream`。
- 单段 Range 支持首尾范围、开放末端、后缀、超大整数和 `Content-Range`。无法满足的范围返回 416，文件不存在返回 404，授权或路径错误返回 403。
- HEAD 忽略 Range，只返回完整表示的元数据。未知单位或多段 Range 时回退到完整读取。If-Range 没有匹配的验证器时回退为完整请求；缓存策略为 no-store。依据：[RFC 9110 §14](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2)。

## 持久引用与项目文件 IO（2026-10-14）

`ResourceReference` 区分 `relative/path`、`absolute/path` 以及 `url/url/credentialRef` 三种形式。本地资源路径不做 URL 解码，中文、空格、`%` 和 `#` 都原样保留。Windows 盘符和 UNC 路径会规范化，禁止盘符相对路径、ADS，以及越过盘符或共享根目录。在线引用拒绝明文认证和临时目录的授权 URL。

旧的 URL 资源仍然可以读取，相关引用字段作为兼容扩展保留。模型、Tileset 和三维 GeoJSON 的引用在旧场景迁移、SceneDocument v3、Desktop 桥和运行时投影之间保持一致，不会生成页面相对 URL。没有准备好数据的引用资源，不能当作已加载的二维数据集。

原生项目打开时，会把带类型的相对引用解析成工作副本里的绝对路径。保存时只对待写入的副本重算：目标目录内的文件用相对路径，目录外或跨盘的文件保留绝对路径。这个过程不复制资源，也不修改编辑状态和撤销历史。另存文件对话框打开前会记录来源项目路径，期间切换项目不会改变旧快照的解析基准。临时协议 URL 不允许作为模型资源 URL 写进这条链路。

本批验证结果：全仓构建和单测通过；Desktop 的最终生产构建通过，268 项单测通过，5 项因环境原因跳过；1366×768 下全量浏览器 E2E 60 项通过。引用专项覆盖中文路径、UNC、跨盘另存、重开等价、源对象不变、临时 URL 拒绝，以及对话框打开期间切换项目。浏览器 E2E 验证了既有的真实模型和保存/恢复流程，本地引用的原生渲染组合尚未验收。

后续还需要接入原生目录授权的生命周期、父目录重定位和统一的添加数据界面，并完成实际 GLTF/Tileset 的引用加载与另存重开组合。系统文件选择、Windows 125% 缩放、两套不同变换 Tileset 的 LOD、效果与 GPU 清理仍未验收。

## 运行时引用解析与授权生命周期（2026-10-14）

`createCesiumDocumentRuntime` 的 `resolveReference` 回调只处理脱离源文档的渲染副本。它返回的协议 URL 用于加载模型、Tileset 和 GeoJSON；`getDocument()`、Project、保存文件和草稿里仍然是原始引用。准备阶段会检查 AbortSignal 和更新序号，失败或已过期的解析结果不会替换已经显示的场景。

Desktop 的 `createLocalResourceSession` 为已挂载的三维工作区复用项目目录授权。目录外的资源必须显式授权；路径按段比较，不能靠名字前缀相同的目录扩大授权范围。工作区销毁时先结束运行时，再撤销目录授权；销毁之后才返回的异步授权也会被撤销。项目 ID 相同但 epoch 不同时会重新挂载，避免重新打开项目时复用上一个会话的授权。

新项目第一次保存后，现有会话会读取新的资源基准。恢复出来的未保存副本保留来源项目的资源基准，正式保存路径仍然为空；这个基准受 epoch 隔离，不会带到下一个项目。比较正式文件和草稿时会把相对引用规范化，避免仅因磁盘上的相对路径与工作区的绝对路径不同而误判内容。

真实 Tauri 验证把 URL 模型改成 `本地模型/塔楼 #%.glb` 对应的本地绝对引用，检查相对路径的正式文件里不含临时 URL。强制退出并恢复草稿后模型重新显示，再经原生保存链路写入新文件。模型显隐像素为 65359→17197→65349。报告和恢复截图对应隔离应用 `1791979440848`，结束后恢复普通 debug 配置并关闭自有应用和服务。

全仓构建和单测通过，Desktop 271 项通过，5 项原有环境测试跳过；laptop 尺寸下全量浏览器 E2E 60 项通过。当前原生渲染证据只覆盖 GLB。外部 GLTF 依赖仍只有协议传输和解码的证据；Tileset、GeoJSON 引用加载、正式文件重新打开、跨目录另存和父目录重定位仍需专项验证。通用的添加数据窗口和显式目录授权入口还没有接入，本地引用的案例是通过验收夹具准备的。系统文件选择器和 125% 缩放尚未验收。

## 文件和目录重定位入口（2026-10-16）

三维对象的“数据源”检查器中现在可以打开“重新定位本地资源”，选择替换当前文件或替换所在目录。目录模式以所选资源的旧父目录为基准，逐一预览受影响的对象和新旧路径，只替换同一目录及其子目录中的引用。Windows 原生选择器返回的目录，或用户明确填写并应用的目录，会进入当前资源会话的授权范围，底层仍由原生目录协议检查规范路径。

应用只更新资产引用，保留节点、变换、样式和依赖文件的相对结构，并提交一次可撤销的命令。这个过程不移动磁盘上的文件；加载失败时对象和失败状态都保留下来，便于重试。项目 epoch、资产引用冲突和继承锁都在提交前检查，任一项失败都不会出现只改了一部分引用的状态。

浏览器 E2E 已覆盖目录预览、取消、一步撤销/重做、真实项目下载和重新打开；单元测试覆盖单文件替换、目录隔离、冲突、锁定和另存路径重算。本节更新的是产品里的引用流程；Windows 文件和目录选择、外部 GLTF/Tileset 的真实依赖加载，以及跨目录另存组合仍需原生验收。此前章节的批次结果按历史记录保留。

## 无截图的原生资源生命周期验收（2026-10-16）

运行 `rtk pnpm --filter @desktop-webgis/desktop test:native-resources`。脚本使用独立的应用标识、WebView2 profile 和测试目录，连接真实的 Tauri WebView；只断言运行时状态、依赖响应和实际磁盘内容，不截图。结束时关闭自有应用和服务，并恢复普通的 debug 构建配置。5197 和 9229 端口必须空闲，不能与其它占用这两个端口的原生验收并行运行。

本批报告的四组场景全部通过：外部 GLTF 的几何、UV 和 PNG 在中文与 `#%` 路径下加载；原生保存相对引用后终止进程再重开；通过重定位窗口填写新路径，实际加载新目录的依赖；跨目录原生写入副本，保留编辑状态、当前文件和原文件字节，目录外的资源保持绝对引用。重启后旧目录的授权 URL 返回 403，报告里不保存临时的授权 key。

文件路径由验收夹具提供；重开走的是真实文件读取、引用解析和 Store 加载；跨目录写入直接调用 `saveSnapshotToPath`。这些结果不覆盖系统选择器、打开菜单和另存对话框；本轮系统对话框没有被辅助功能工具识别，仍需验收。Tileset 和 GeoJSON 的引用生命周期、Windows 125% 缩放和最终的全矩阵仍列为未完成项，视觉细节交给用户验收。

## 三类资源与外部目录重新授权（2026-10-16）

后续验收补齐了 GLTF、嵌套 Tileset 和 GeoJSON 的共同加载、原生保存与退出重开，以及目录重定位。Tileset 会真实请求根 JSON、子 JSON 和中文路径的 GLB，GeoJSON 创建独立的 Cesium datasource；重定位后会再次请求新目录中的依赖，托管层和 datasource 数量保持正确。测试夹具已移入仓库的 `.artifacts/`，避免并行运行 Playwright 清理 `test-results/` 时把原生资源删掉。

本轮发现并修复了一个授权缺口：外部路径在另存副本重开后，之前如果路径没有变化，「应用重定位」是禁用的，导致无法重新授权原目录。现在在桌面应用中选择“替换所在目录”并填写资源当前的父目录，会出现“授权目录并重新加载”。点击后只授权当前项目会话并刷新资源，不修改引用、项目的未保存状态和撤销历史；项目代次变化时则拒绝。不同目录仍走原有的重定位命令，浏览器端不显示这个授权操作。

原生授权报告包含 7 组通过的场景：另存副本重开时先拒绝未授权的外部路径，显式授权后加载全部三类资源，前后的项目快照、未保存状态和历史可用性一致。317 项单测、两个尺寸的资源重定位 E2E 和生产构建均通过，没有截图。这个受控的小数据案例不代表大规模 Tileset 的 LOD 和性能验收；系统选择器、Windows 125% 缩放以及 E01–E20 全矩阵仍待完成。
