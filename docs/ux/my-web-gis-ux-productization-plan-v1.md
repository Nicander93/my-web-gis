## 0. 产品目标和实施边界

这轮不是重新建设二维 GIS 能力，而是将已经工作的功能从“演示型功能堆积”变成用户能够自然完成任务的**专业桌面 GIS 工作区**。

**成功判据**：用户导入图层 → 在图层树定位对象 → 编辑样式/标注 → 打开多图层属性表 → 搜索/筛选/选择 → 计算字段 → 识别要素信息 → 查看任务进度 → 保存项目。无需反复寻找入口、重复选图层、频繁切换不相干面板，也没有因 UX 调整造成项目或数据损坏。

**不可更改的前提**

1. 保留现有 React、Tauri 2、Zustand、OpenLayers、GIS Core、项目存储及编辑历史，**不重写地图引擎**。
2. 维持已经实现的 MapLibre Style Specification v8 数据结构和 GIS Layer ↔ 多个 Style Layer 绑定；保留 `ol-mapbox-style + Canvas` 及现有 WebGL 可选路径。
3. 保留可用的 SLD 单向导出和 GeoServer REST/MBStyle 发布实现；这轮**只调整用户入口与工作流**，不重新实现发布内核。
4. 优先保证**基础功能稳定可用**，不因为原型展示了高级能力就追加引擎特性。
5. 优先复用已有 UI 组件与 Token。HTML 原型只表达结构/行为，不允许逐个复制独立 CSS 到生产代码。
6. 暂不触碰三维业务结构；全局设置和右侧窗口基础设施必须兼容后续三维共用。

## 1. 原型优先级和已确认决策

HTML 原型不是单一“最终视觉真理”：不同时间的版本会有冲突。**以下用户最终决策覆盖旧原型。**

| 模块 | 主参考原型 | 已确认行为 / 实施修订 |
|---|---|---|
| 整体工作区 | `my-web-gis-workspace-ux-v1.html` | 地图优先、顶部紧凑工具区、左右可收起、底部仅保留属性表；任务/诊断独立非模态窗口。 |
| 图层树 | `my-web-gis-layer-tree-ux-v1.html` | **本次补充原型，待用户最终体验**；只整顿密度、图例、右键菜单，不增加底层能力。 |
| 属性表 | `my-web-gis-attribute-table-ux-v3.html` | 小图标工具栏、表格占主体；上方图层选择器**改为可关闭 Tab**，各 Tab 保留独立视图状态。 |
| 表格搜索/筛选 | `my-web-gis-attribute-table-ux-v4.html` | 仅沿用视觉/标签反馈；**用户已明确取消属性表中的“图层筛选”模式**。属性表保留表内搜索+表格筛选，两者均不改变地图图层可见性；其他入口的图层过滤功能可维持。 |
| 字段计算 | `my-web-gis-field-calculator-ux-v1.html` | 独立可调整窗口，新建/覆盖二选一、范围明确、多行表达式、5 行预览、整批校验/原子修改/撤销。优先当前引擎已支持函数。 |
| 右侧图层属性 | `my-web-gis-right-inspector-ux-v3.html` | **删去其“要素”页**，保留「图层 / 样式 / 标注」，紧凑表单，常用设置就地修改。 |
| 右侧竖向栏 | `my-web-gis-right-toolrail-ux-v1.html` | 最右侧「属性 / 信息 / 处理」垂直入口；同一时刻只展开一个面板。窄窗口避免与左侧遮挡。 |
| 要素识别/信息 | 右侧竖栏原型 | 识别工具属于地图顶部工具；**点击“信息”竖栏只查看已有识别结果，绝不改变当前地图工具模式**；识别点击可自动展示信息结果。 |
| 日常样式 | `my-web-gis-right-style-inspector-v2.html` | 单符号先看符号，分类/分级时先看规则；高频颜色/大小直接编辑，低频复杂项打开专业弹窗，保留表达式。 |
| 专业制图 | `my-web-gis-style-editor-v4.html`、`my-web-gis-line-symbol-editor-v1.html`、`my-web-gis-symbol-library-v1.html` | 旧原型作为工作流/布局参考；不能把原型的全部示例符号都当作生产系统已有。当前分支 `symbol-library.ts` **仅定义 9 个内置示例预设**。 |
| 全局设置 | `my-web-gis-global-settings-ux-v1.html` | 独立设置窗口，从顶部「设置」打开；外观、界面字号/密度、关于/更新；AI Agent **暂不提供不可用配置页面**。 |

**重要：**已有 `my-web-gis-2d-cartography-technical-design-v1.1.md` 是此前 `main` 基线上的*前瞻设计*；新分支已实现其中多项能力，不能让 Agent 再按该文件从零开发一次。

## 2. 全局交互与视觉契约（所有阶段生效）

### 2.1 组件密度

| 元素 | 默认建议 | 约束 |
|---|---:|---|
| 标准 UI 字体 | 12–13px | 可通过全局设置 11/12/13/14 调整；地图符号/标注不受影响 |
| 常规输入/按钮 | 26–28px | 不为了统一而把可点击图标缩至难用 |
| 图标按钮 | 24–26px | 14–16px 线性图标，悬停/焦点提示 |
| 表格行、图层行 | 26–30px | 表头/行高一致，选中状态清楚 |
| 标签页 | 28–30px | 关闭按钮及溢出导航可操作 |
| 分组间距 | 6–10px | 多用间距与细分割线；避免厚卡片/重复标题 |
| 状态栏 | 22–26px | 容纳任务、诊断入口与地图状态，不挤占表格 |

基于现有 `apps/desktop/src/styles/tokens.css` 和 `DesktopUiProvider.tsx` 做统一配置。原项目已有 `componentSize="small"`、12px 字号，但 CSS 包装层、整行按钮、表单节距和标签重叠导致实际密度偏低；禁止通过全局 `transform: scale()` 伪缩小。

### 2.2 单一职责、行为统一

- 图层树选择图层 ≠ 激活编辑目标：后者必须明确显示；操作目标不随无关点击悄然变更。
- 右侧「属性/信息/处理」是**工作面板**的切换；「图层/样式/标注」是**属性面板内标签**，不要混到同一级。
- 任务、诊断是独立非模态窗口；关闭窗口不会取消运行中的任务；不能占据属性表 Tab。
- 样式字段/颜色/符号实时修改，Ctrl+Z 按一次用户操作撤销，Ctrl+S 保存项目，不恢复草稿式强制“应用”。
- 低频功能归位右键菜单/次级菜单，不为“可发现性”将所有按钮重新摊满页面。
- 无项目、无图层、只读、无识别记录、错误/加载中各有真实可操作的状态；错误消息短、明确、可恢复。

## 3. 工作包与执行顺序

### P0 · 基线保护与设计系统（先做）

**改动重点**：不改 GIS 业务，建立统一桌面尺寸、层级、图标操作、窗口壳、焦点及键盘规则。

- 从最新分支创建 UX 重构工作分支；检查现有构建、测试及 E2E 能否运行，保存基线结果。清查关键窗口/样式/任务状态逻辑。
- 在 Tokens / DesktopUiProvider / 共享组件中统一尺寸。移除局部重复标题、大面积说明、无意义卡片、同级四按钮堆叠。
- 在 1440×900、1024×680 下做窗口边界、滚动、键盘焦点检查。保留 Tauri 与浏览器环境差异。

**验收**：旧功能可正常打开，缩放/滚动/Tab/焦点无回归。无“功能隐藏了但再也找不到”的问题。

### P1 · 工作区与窗口职责

**现有定位**：`Workspace.tsx`、`BottomPanel.tsx`、`ActivityPanel.tsx`、`ViewMenu.tsx`、`view.commands.ts`、`DockWindow` / docking stores。

- 底部 `BottomPanel` 只服务 `AttributeTableHost`；去掉属性表/任务/诊断三合一 Tab。
- 任务中心、诊断中心从状态栏和顶部「窗口」菜单访问；各自独立非模态窗口，支持关闭、再次打开、合理的默认尺寸和层级。
- 建立右侧固定竖向工具栏「属性 / 信息 / 处理」，共享内容容器。切换工作面板不改变地图当前工具；窄窗口可收起左侧，且有明确恢复入口。
- 图层属性的「要素」页移除，迁到独立“信息”结果面板。工具栏“识别信息”负责启动识别；竖向“信息”仅打开已有记录（空结果也能打开空态）。
- 窗口菜单统一名称与 checked 状态，避免一处叫诊断一处叫日志。

**验收**：属性表打开时查看任务/诊断不切换或重置属性表；信息入口不更改 `getActiveEditTool()`；窄屏没有遮挡重要按钮，左右面板可手动恢复。

### P2 · 属性表基础可用性（优先于高级功能）

**现有定位**：`AttributeTable.tsx`、`AttributeTableHost.tsx`、`FieldCalculator.tsx`、`FieldSchemaDialog.tsx`、`field-edits.ts`、`workbench.store.ts`、`session.store.ts`。

- 上方多图层视图改为**可关闭 Tab**（不要同时保留冗余下拉框）；打开/切换/关闭图层时保留各 Tab 的搜索、筛选、列宽、排序、滚动位置。
- 一行紧凑工具栏：搜索框 + 必要的图标操作；固定底部数据状态：总数/当前显示/选中/分页 + “仅显示选中”。不默认占用约 220px 展示技术 ID，允许从列显示中恢复。
- **表内搜索 + 表格筛选**：都只影响当前属性表视图，不改变地图或项目级图层过滤；清除筛选后恢复全部视图，生效条件可见、可删除。用户明确拒绝在属性表增加“表格筛选/图层筛选”的双模式。
- 记录选择与地图选择集同步；Ctrl/Shift 的范围选择、仅选中显示、定位行为定义清楚。不让只读单元格的 Enter/双击意外修改操作目标。
- 属性表直接进入统一编辑会话；字段管理/计算器复用既有权限、锁定、撤销体系。单元格非法输入必须保留草稿及错误，不能直接退出导致丢内容。
- 区分**列显示（视图状态）**与**字段结构（数据变更）**。隐藏、调整顺序和宽度不改数据；重命名/删除需统一检查 MapLibre 风格 `get` 表达式、标注、图层过滤、弹窗引用。

**验收**：两张属性表往返不丢各自状态；筛选不会修改地图要素显示；计算/单元格编辑可撤销，关闭重开项目数据正确；受限图层只读状态明确。

### P3 · 字段计算器（只做够用的专业能力）

- 独立可调整窗口；新建字段/覆盖字段明确二选一；范围（全部/当前表格结果/图层过滤后/选中）与记录数始终一致。默认不要暴露底层内部 ID。
- 多行表达式输入，字段/函数快速插入，提供少量样例结果和类型/空值/表达式错误。预览基于真实引擎而非浏览器 `eval`。
- 复用当前 `packages/spatial-analysis/src/field-calculation.ts` 的 `jsep` + 白名单 AST 实现；**当前仅支持 `field`、`coalesce`、`round`、`concat`、`abs`、`min`、`max` 等有限函数与三元表达式，不支持 SQL `CASE WHEN`**。UI 不要承诺未实现函数。
- 执行前对目标范围进行完整校验；任一错误则不做部分提交；成功以一条编辑历史记录提交，允许撤销。耗时任务有非阻塞反馈。
- 本轮不实现复杂 SQL、任意 JavaScript、空间关系函数或大规模后台作业调度。若用户实际需要，单独立项。

**验收**：5 种表达式与失败场景；覆盖已有字段前能看清目标和数量；预览与执行数值一致；失败后数据零变更。

### P4 · 右侧属性、标注与样式工作流

**现有定位**：`Inspector.tsx`、`StylePanel.tsx`、`LabelPanel.tsx`、`SymbolEditor.tsx`、`SymbolLibrary.tsx`、`useCartographyEditor.ts`。

- 右侧属性内只保留「图层 / 样式 / 标注」，默认常用属性直接编辑；避免“图层属性”标题下再重复标题。
- 样式页面：符号预览最醒目，选择/编辑符号入口明确；分类/分级列表按需展示；常用参数即改即生效；低频 SLD、GeoServer 转至图层右键/样式菜单。
- 消除“专业样式已修改 → 整个基础样式面板变只读”的工作流割裂。只对**确实无法被基础控件安全表示的单项属性**给出表达式入口，不重写合法未知 AST。
- 标注页控制常用字段/字号/色彩/描边/位置；点/线/面显示与其几何相符的选项。高级规则暂不扩散到侧栏。
- 专业符号窗口和符号库沿用先前认可的结构，先修预览、参数层级、交互与资源引用；不以示例库数字为新功能验收目标。

**验收**：改简单点符号颜色只需少量操作；多层样式/Zoom 表达式往返基础面板不被破坏；每次修改进入正确的撤销历史；原有 SLD/GeoServer 发布命令仍可用。

### P5 · 图层树、菜单归位、全局设置与收尾

- 图层树从现有 `LayerPanel.tsx` / `LayerContextMenu.tsx` 渐进调整：紧凑 26–30px 行、图层组、名称、可见性、选中、编辑目标、图例展开、右键菜单；保留已实现拖放排序。默认不堆满图标，更多命令按分组组织。
- 一次单击只选中图层；右键菜单围绕该图层提供常见“定位、属性、样式、标注、属性表、导出、发布”。图例仅用于查看子分类，**不可被误当成 GIS 数据图层**。
- 顶部「设置」改为真正的软件设置入口；原先混入设置菜单的数据/图层/编辑命令移回 Ribbon 或相应业务菜单，保证原命令不丢失。
- 软件设置存储独立于项目：UI 字号、紧凑/标准密度、主题；关于/构建版本、检查更新入口。正式 updater 没接通时展示可理解的不可用状态，不虚构“已最新”。AI Agent 设置本轮不做空壳表单。
- 修复 UI 组件尺寸不一致、横纵滚动与层叠、可访问性与小屏响应；形成 UI 像素基准截图。

**验收**：图层选中/拖放/显隐/图例/右键仍正常；字体和密度设置不会改变地理地图标注大小；重新打开应用设置有效；三维基本工作区没有意外回归。

## 4. 全流程人工与自动验收

按真实任务走通，而不是只检查组件截图：

1. 1440×900：导入两份 GeoJSON / SHP，图层树排序、开关显示、图例展开、搜索图层；右键进入样式。
2. 给河流数据做分类，调整颜色；切换多层样式，撤销/重做，保存并重开工程，表达式保持。
3. 打开两个图层属性表 Tab，各自搜索/排序/列显示；关闭其中一个 Tab 再打开，检查数据和选择集不串层。
4. 仅在属性表中筛选记录，地图图层显示不被篡改；选择记录后在地图高亮，地图选择反向同步属性表。
5. 进入属性编辑，改单元格；用字段计算器新增/覆盖字段、预览、成功一次撤销；制造除零错误确认没有部分写入。
6. 打开任务中心和诊断窗口，属性表持续显示；关掉任务窗口后运行状态仍存在；点击“信息”竖栏不改变地图工具。
7. 使用地图识别工具点击两个不同图层，信息结果面板查看记录；关闭/切换右侧工作面板不会误启动操作。
8. 从图层右键重新找到原有 SLD 导出和 GeoServer 发布流程（测试环境/Mock），业务结果与之前一致。
9. 1024×680、1440×900 两档核查：面板无不可达控件，滚动只发生在预期区域；焦点、Esc、Enter、工具提示可用。
10. Windows/Tauri 冒烟：窗口拖动和关闭、系统主题变化、设置持久化；浏览器 E2E 无法替代这一步。

**不做**：这轮不补完整内置符号库、不做 SLD 反向导入、不实现高级字段 GIS 几何表达式、不重写 GeoServer、不增加三维造型功能。

## 5. 交付方式和工程质量门槛

- 每个 P 阶段尽量拆成**可独立验证的提交/PR**；不要一个 PR 同时大改框架、样式引擎、属性数据层、UI。
- 先迁移测试再删旧实现；对破坏性操作增加真实单测/E2E。测试断言应检查数据和行为，不只检查按钮是否存在。
- 保持当前项目运行方式。不要引入全新大型 UI 框架；除非现有组件无法支持，才提出明确的替代论证。
- 对设计和原型不一致之处，**以第 1 节“最终确认决策”优先**；依旧模糊的极小细节在不改变架构前提下自主采取简化方案。
- UI 结果可使用真实代码的屏幕截图与原型并排评审；优先评估操作路径、密度和可读性，而非形式像素级一致。
- 提交前报告：变更范围、复用的现有模块、通过的测试、仍无法确认的原生/远端功能，以及没有实现的项目。

## 6. 尚未确认，禁止擅自扩大范围

1. 左侧图层树新增原型是**保守方向稿**，尚未单独获得用户最终审阅；只应做明确的密度/操作修整，不根据示例创造新的图层概念。
2. 是否保留图层级过滤入口：**本轮只移除属性表内的图层筛选模式**，不等于删除项目其他位置已有的图层过滤能力。
3. 全局自动更新、AI Agent 服务商/模型/权限、跨图层高级识别历史等不属于本轮可用性验收目标。
4. HTML 中的模拟地图、任务、计算器或资源预设不可当作已完成生产实现；必须复用真实命令与数据。
