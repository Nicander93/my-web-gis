# 给开发 Agent 的执行指令 · my-web-gis UX 产品化 V1

你正在改造 `Nicander93/my-web-gis` 的二维桌面 GIS 工作区。**先阅读随包交付的 `docs/ux/my-web-gis-ux-productization-plan-v1.md` 与 `docs/ux/prototype-index-v1.md`，再动代码。**

## 不要跳过的准备

1. 获取远端代码，核对分支 `codex/2d-cartography` 当前 HEAD（评审基线 `c2a12a4f9f004a96c362f13b0eab488f458a0018`）及是否已合并 `main`。**不要在旧 main 上重复实现已经在功能分支完成的制图/发布能力。**
2. 检查工作区是否有未提交修改，保护它们。建立单独 UX 工作分支。先运行现有测试/构建，记录测试基线和环境限制。
3. 打开 HTML 原型，对照真实 React 实现建立变化清单。**用户确认的行为决策高于相互矛盾的旧原型**；不要将 HTML 模拟逻辑原样搬进生产。

## 目标

这是 UX 产品化，而不是新功能开发。用统一的紧凑桌面设计系统，完成：右侧属性/信息/处理竖向栏、独立任务与诊断窗口、底部多 Tab 属性表、表格局部搜索/筛选、字段计算器专业工作流、右侧样式与标注、图层树操作密度、全局设置。

## 关键不可违背的决策

- 「信息」竖栏**只打开已有识别结果**，绝不能切换地图为识别工具。顶部「识别」地图工具负责新增识别。
- 右侧图层属性仅保留「图层/样式/标注」；要素信息脱离属性标签，进入独立“信息”工作面板。
- 属性表**只做表格筛选与搜索**，不提供“图层筛选”模式，不意外改变地图要素的显示；其他已有图层过滤命令不得被无故删除。
- 底部只放属性表。任务和诊断用状态栏/“窗口”菜单打开独立非模态窗口，关闭窗口不取消任务。
- 多个属性表通过**可关闭 Tab**切换，Tab 状态独立；工具栏少量图标 + Tooltip，紧凑但可点击。
- 字段计算：新建/更新区分、表达式输入、5 行预览、目标数明确、整批预检、原子执行、一次撤销；先沿用 `jsep` 白名单表达式引擎，不支持随意脚本。
- 基础样式编辑**不能因为存在一个高级 MapLibre 表达式就整页只读**；单参数安全编辑，不能丢未知标准 AST。
- GeoServer/SLD/MBStyle 内核已在新分支实现，**不要重写**；只是把低频发布入口归入合适菜单。
- 全局设置独立于项目，AI Agent 未接入时不展示假配置或承诺真实更新能力。
- 视觉密度统一：常规控件 26–28px、表格/树 26–30px、12–13px 字体、14–16px 图标，低饱和灰白绿，无卡片堆积和常驻教学文案。

## 执行顺序

按照计划书 P0→P5 实施，每一步完成后自行测试、修复并简明报告：

- P0：基线与共用 Token / 组件。
- P1：工作区与窗口职责、右侧竖栏及信息识别。
- P2：属性表、Tab、表格筛选与编辑。
- P3：字段计算器与原子计算。
- P4：样式/标注/符号体验整理。
- P5：图层树、菜单归位、设置与全流程验收。

**不要因要交付的范围较广而一次性无验证地改完所有代码。** 先完成 P0/P1 的小闭环，确认未破坏现有 GIS 功能，再继续。每个阶段单独提交，保证用户可在中途停止。

## 完成定义

- 完成计划书第 4 节的 10 个真实场景，能提交基线对比与截图。
- 保留原有数据和项目兼容性、编辑历史、样式、SLD 导出、GeoServer 发布及二维/三维工作区。
- 说明任何未验证的 Windows/Tauri 行为或真实 GeoServer 行为，不把模拟测试当作原生实测。

若你对某个细节不确定：不要退回到功能入口堆叠；优先选择**用户路径最短、UI 最克制、代码改动最小**的实现。重大架构变更必须先报告理由。
