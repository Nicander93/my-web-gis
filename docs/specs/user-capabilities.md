# 用户功能清单与改进顺序

本清单替代 S00–S10 的整包排期，按用户操作跟踪能力。代码存在、浏览器验证、Windows 原生验收分别记录，不以“有接口”代替产品完成。

## 产品原则

- 地图／场景是主工作区；工具、表单和属性表只占必要空间。
- 一个任务有明确入口和目标，浏览选择与编辑目标分开。查看不自动打开大型面板。
- 表单以单行标签和紧凑控件为主；说明放在提示或帮助入口，不常驻占空间。
- 常规属性修改实时生效并可撤销；需要检查或准备的数据导入保留明确确认步骤。
- 少用重复标题、分组解释和演示文案；分组表达真实任务关系。
- 选择、表格、定位和历史必须一致；失败、取消和关闭不留下旧资源或半份结果。

## 已提供的工作流

| 工作流 | 当前能力 | 验证与边界 |
| --- | --- | --- |
| 创建与继续工作 | 创建二维地图／三维场景，打开和保存项目 | 两类工作区分别编辑；不提供项目类型转换 |
| 二维数据组织 | 本地矢量导入，WMS／WMTS／WFS，图层排序、分组、显隐和属性 | 文件格式及服务配置以导入器支持项为准；WFS 是本地快照，不是 WFS-T |
| 二维要素操作 | 点击、框选、加选／减选，属性表联动，双击记录定位 | 浏览器已有证据；图层字段过滤与选择共同生效 |
| 二维样式与处理 | 样式、标注、过滤、空间处理及结果图层 | 草稿应用与切换有独立流程；空间连接默认最多 100000 条，超限整次失败 |
| 三维内容编辑 | 模型、Tileset、GeoJSON、影像、图形和水面；对象分组及显隐 | 仅原生三维对象，二维 vector／tile 不自动显示在三维 |
| 三维编辑与画质 | 移动／旋转／缩放、对象属性实时修改、场景质量设置 | GLB 浏览器像素、历史及加载失败重试已有证据；硬件 GPU 和原生窗口不据此签收 |
| 场景交付 | 第 3 版场景 JSON、ZIP 资源包，旧场景迁移及内部运行时 | 保存内容不等于跨引擎同渲；引用的本地资源需满足打包约束 |
| 坐标系 | 4490、CGCS2000 3° 无带号 4534–4554、带号 4513–4533；二维视图切换 | 4490／4326 是椭球近似，没有格网改正；分带视图要求当前中心在对应分带内 |

## 当前缺口与限制

- Desktop 已接通“地图可选择”及二维 Popup 配置与显示，相关验证见 [选择策略](../plans/map-selectable-policy.md)和 [弹窗交付记录](../plans/map-popup-workflow.md)。Viewer 已有按配置显示 Popup 的路径，仍需单独验证显隐和过滤边界。
- 表格键盘与二维历史、定位及地图取消已有浏览器验证，见 [键盘交付记录](../plans/table-keyboard-workflow.md)；Windows 实际输入法仍未签收。
- 嵌套分组、多视图及任意文档的完全无损工程往返未签收。Desktop 会规范化底图 ID，部分工程导入比共享文档校验更严格。
- 旧 v3 中由三维影像迁移成的 tile 缺少来源标记，按二维节点保留；从原始 CityScene 重新导入才能保留原生 imagery 类型。
- 原生文件窗口、取消后的本地缓存清理及真实硬件渲染仍缺原生验收。
- 数据源仍可能限制底图清晰度；提高渲染分辨率不能增加原始影像细节。

## 不承诺的内容

二三维同渲及交互对等、三维 WMS／鉴权瓦片／复杂分级符号、公共包 npm 发布、北京 54／西安 80及格网改正均不在当前排期。内部包保留清晰边界，不扩大成新的 SDK 发布工程。

产品取舍与验收由当前任务承担。每刀完成实现、范围匹配的测试和记录后审查合入；不等待另一个产品角色，也不把可选项同时展开。
