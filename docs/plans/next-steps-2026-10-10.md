## 2. 已做的决定

1. **冻结「一份场景文件二三维同渲」。** 不再追城市树写回投影图层、跨引擎显示对等、跨引擎 selectable／Popup。二维和三维各自在自己的工作区编辑和查看。
2. **对外不承诺同渲。** 用户功能清单里写明这一点（产品经理负责）。
3. **城市树写回这一刀取消。** 本地分支 `feat/city-tree-scene-writeback` 已删除，没有推送过。
4. **main 上不大删。** 共享 `SceneDocument`、场景 JSON／ZIP、二维和三维各自的能力互相依赖，保留。只服务同渲的代码通过单独的清理 PR 处理。
5. **公共包暂不发布到 npm。** `packages/` 里的包目前当作应用内部的分层，只有修产品缺口必须改包，或者明确决定要对外或给 Viewer 用时才专门动。
6. **继续小 PR。** 每一刀都有产品勾选项，开发主管门禁，产品勾选后 squash 合入。只在本机 LM 上开发，不用 Cursor 云端代理。

## 3. 下一步（按顺序）

### 3.1 同渲冻结清理（下一刀，尚未开工）

从当前 main 开分支，例如 `chore/freeze-co-render-cleanup`。产品勾选项已经定好：

1. 用户界面上不再出现「三维里当二维图层用」这类入口或暗示（菜单、说明、默认行为）。
2. PR 里附 KEEP／REMOVE 清单，每项带文件路径。共享文档、JSON／ZIP、二维／三维各自编辑一律 KEEP；只删除或关闭明确只服务同渲投影的路径。
3. 现有门禁保持全绿；如果误伤导入导出、三维模型或 tileset，这一刀不算通过。

做法：先藏入口，再按调用关系确认哪些代码确实没有其他调用方，最后才删。拿不准的先保留，在 PR 里标成「实验能力，未启用」。
