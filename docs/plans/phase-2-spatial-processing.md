# 第二阶段：空间处理工作流

更新：2026-10-02。用户要求优先开发实际功能，保留架构边界并改善产品体验。

## 产品目标

用户能从已有矢量图层选择输入范围，运行处理，得到独立结果图层，然后继续处理、检查属性、编辑、保存项目或导出。

工具实现优先复用成熟第三方库：按能力选择并锁定版本，保留薄适配与契约测试。库缺失或不能满足产品语义时再独立实现，并记录原因；不自行重写布尔几何等复杂算法。

参考 [GeoLibre Processing 文档](https://geolibre.app/user-guide/processing/) 的工具分类与工作流。优先补齐本项目的常用矢量任务，按实际用例安排工具；暂不引入 Python/GDAL、插件系统或二三维统一框架。

## 已实现的第一批

入口：**数据 → 空间处理…**。

| 工具 | 输入与结果 | 明确的语义 |
| --- | --- | --- |
| 缓冲区 | 点/线/面 → 每个要素的缓冲面 | 距离单位为米/千米，正距离；保留属性，不自动融合 |
| 顶点质心 | 每个要素 → 一个点 | 顶点坐标平均，闭合重复顶点不计；不是面积加权质心，也不保证落在面内 |
| 整体外包矩形 | 当前输入范围 → 一个矩形面 | 结果属性记录 input_count；退化为点/线时报错 |
| 多部件拆分 | 多点/多线/多面 → 单部件 | 单部件也复制为独立结果，保留属性、面环和孔洞 |

缓冲与质心使用精确锁定版本的 Turf 子模块，避免自行实现复杂几何算法。算法语义参考 [buffer](https://turfjs.org/docs/api/buffer) 与 [centroid](https://turfjs.org/docs/api/centroid)。

外包矩形和多部件拆分也已改用 Turf `envelope` / `flatten`；项目仅保留坐标契约、退化范围校验、属性与标识管理。

## 已实现的第三批：按位置提取

点、线、面及其多部件均可作为第一输入，第二输入为面图层。多个范围先使用 Turf union 合并，再用 JSTS 2.7.1 的 GeoJSONReader / RelateOp 判断完整几何关系；复用成熟拓扑实现，不用顶点采样近似线、面包含关系。库支持与导入方式参考 [JSTS 官方仓库](https://github.com/bjornharrtell/jsts)。

| 关系 | 规则 |
| --- | --- |
| 相交 | 有任何共同位置，包括外边界或孔洞边界接触 |
| 完全位于其中 | 整个要素不越出合并范围，且内部与范围内部相交；边界点、仅沿边界的线不符合 |
| 不相交 | 没有共同位置；位于孔洞内部的要素可符合，边界接触不符合 |

每个匹配要素仅输出一次，保留完整几何与属性；这是提取而不是裁剪。延续全部/筛选/选中范围、输入快照、Worker 取消、独立结果及来源保存流程。无匹配时明确提示，不创建空图层、不标记项目修改。暂不支持距离谓词或跨日期变更线输入。

## 已实现的第二批：面运算

继续使用相同入口、Worker 与独立结果图层流程，新增：

| 工具 | 几何规则 | 属性规则 |
| --- | --- | --- |
| 面裁剪 | 第二输入先融合为掩膜，再逐要素相交，避免重叠掩膜造成重复结果 | 仅保留输入 A 的属性 |
| 面相交 | A/B 按要素对相交；每个非空配对形成结果，可能保留多部件 | 全部 A 字段加 A_，全部 B 字段加 B_，避免覆盖 |
| 面差集 | 第二输入先融合，从每个 A 要素扣除；完全覆盖的要素不输出 | 仅保留 A 的属性 |
| 面融合 | 全部融合或按字段分组，支持孔洞和不相连部件 | 不分组时清空属性；分组仅保留该字段，不自动统计 |

底层复用 Turf 7.3.4 的 `intersect`、`difference`、`union`、`boolean-valid` 和 `kinks`。参考官方 [intersect](https://turfjs.org/docs/api/intersect)、[difference](https://turfjs.org/docs/api/difference)、[union](https://turfjs.org/docs/api/union)；融合使用 union 来覆盖 MultiPolygon 与分组语义。

- 当前仅接受纯面图层的 Polygon / MultiPolygon；点、线与混合图层不会列入面工具候选。线裁剪尚未实现。
- 第二输入 B 独立选择范围并显示数量，遵循同一筛选/选择契约；其名称、范围和输入数量也随处理来源保存。
- 仅边界接触不输出面；无相交结果显示说明，项目不变，不创建空图层。
- 空值与缺失字段归入同一空值组；数字 1 与字符串 "1" 不归为同组。复杂属性不可选为分组字段。
- 拒绝自相交、外环之外的孔洞、孔洞重叠和多面部件面积重叠；使用库运算作附加检查，不自动修复或悄悄丢弃坏要素。不宣称提供完整几何修复能力。
- 面运算按二维经纬度坐标执行；不是测地面积计算，不承诺保留 Z，跨日期变更线输入暂不支持。

### 统一体验

- 一个紧凑对话框：左侧工具，右侧输入、范围、参数和结果名称。
- 全部 / 图层筛选结果 / 当前选中范围；数量随数据、筛选、选择更新。选中范围遵循 S∩F。
- WFS 使用已加载快照，按快照实际数量处理；WMS/WMTS 无矢量几何，不列为输入。
- 输出到新的 Dataset + Layer，不共享可变几何/属性，不改原图层。
- 成功信息显示输入/输出数量，提供“查看结果”；错误在参数区保留，便于修改后重试。
- 计算在 Worker 中，取消/关闭会终止 Worker；失败、空输入、取消不创建结果图层。
- 结果附带工具参数、原图层标识/名称、处理范围、数量和时间；保存重开后在检查器“处理来源”按需展开。
- 焦点限制在对话框内，Escape 关闭，关闭后恢复原焦点；小窗口参数区滚动，底部动作保持可见。

## 架构与数据约定

1. `gis-core/processing.ts`：纯几何计算与参数、几何检查；不依赖 React、DOM、Tauri、OpenLayers 或 Store。
2. Desktop `services/processing.ts`：统一解析范围、管理 Worker 生命周期、提交独立结果图层。
3. `app/commands/processing.commands.ts`：一次完整操作，捕获输入快照；完成后检查取消和项目身份，才能写入项目。
4. `features/processing`：工具参数与反馈，Worker 调用核心计算；界面不操作地图几何。
5. Store 沿用现有本地图层创建方式，Dataset 的可选 processing 元数据随 ProjectSnapshot 持久化。旧项目不需要该字段。

内部几何延续现有 EPSG:4326 契约，地图显示投影不作为处理距离单位。基本检查包括有限经纬度、最小线顶点数、面环闭合；尚未提供完整拓扑有效性检查。缓冲限制在非极区、不跨日期变更线、0～1000 千米正距离；质心和矩形也明确拒绝跨日期变更线输入。结果不会根据原数据的后续变化自动重算。

处理来源是解释结果的记录，不是保证可重放的历史：当前未保存原输入快照与选择 ID 集合。处理结果通过 `AddLocalLayerCommand` 加入 Undo/Redo，同时撤销数据集、图层、顺序和要素缓存；重做恢复同一结果快照与标识。

## 后续实施顺序

| --- | --- | --- |
| B | 面裁剪、相交、差集、融合已实现；线裁剪待补 | 已明确面掩膜、孔洞、多部件、边界相切、空结果与字段规则；线裁剪需先选库 |
