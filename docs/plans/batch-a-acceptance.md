## P01 — 面板行为与上下文保持

### 产品门槛（与开发主管已确认，强制要求）

1. **布局操作不进入 Dirty / 不写入 Undo 历史 / 不写入项目文件**  
   收起、展开、调整面板大小等布局操作不得触发项目"未保存"状态，不得产生 Undo/Redo 记录，不得持久化到项目文件。

2. **收起→恢复保留操作上下文**  
   至少保留：
   - 属性表的搜索条件与滚动位置
   - 右侧面板的当前页签与未应用草稿（按图层区分）
   - 不因面板收起而自动应用草稿

3. **地图点选不强开已收起面板**  
   普通地图点选要素不应自动展开用户已收起的面板；功能入口（如"编辑属性"按钮）可主动展开对应面板。

4. **专注模式进出恢复布局**  
   进入专注模式前记录布局状态，退出后恢复。

5. **重置布局恢复新默认**  
   "重置布局"功能应恢复到产品设计的默认布局，而非启动时的布局。

### 补充检查项（依据计划）

- 窗口 resize 后地图仍可用（无永久遮挡）
- 焦点恢复时有可访问的名称（accessibility）
- 1366×768 和 1920×1080 分辨率下随机抽查，确认无永久的地图控件遮挡

## P02 — 紧凑菜单与固定工具栏

### 产品要求

#### 菜单结构

顶部菜单栏包含以下菜单：

- **项目** (Project)
- **数据** (Data)
- **图层** (Layer)
- **编辑** (Edit)
- **视图** (View)
- **帮助** (Help)

#### 固定工具栏

保留常用功能的直接入口：

- 添加数据
- 保存
- 导航工具
- 选择工具
- 编辑常用工具

#### 核心原则

1. **已有能力仍可达**  
   通过新菜单/工具栏可以完成原有的所有已实现功能。

2. **未实现能力不做虚假可点按钮**  
   计划中未实现的功能不得添加可点击但无实际作用的按钮。

3. **禁用项有明确原因**  
   禁用状态的菜单项应在 hover 或状态栏提示禁用原因。

4. **工具状态与 runtime 一致**  
   工具栏状态必须与应用 runtime 状态保持同步（如无图层时编辑工具禁用）。

### 验收路径

完成以下完整流程，验证新 UI 可达性：

1. 通过新菜单打开 GeoJSON 文件
2. 通过工具栏或菜单进入编辑模式
3. 完成编辑操作（绘制、修改）
4. 执行撤销 (Undo)
5. 执行重做 (Redo)
6. 通过菜单保存项目
7. 通过菜单导出数据
8. 切换菜单不改变当前工具状态

### 键盘与可访问性

- **快捷键在输入框内不误触发**  
  在属性表或文本输入框中按 Delete 键不应触发删除要素；绘制工具快捷键不应在输入时误触发。

- **菜单键盘导航**  
  支持 Alt/Tab/方向键导航菜单，Esc 关闭菜单。

- **布局功能可从视图菜单找到**  
  "重置布局"与"专注模式"应在视图菜单中有入口。

- **OGC fixtures 债务已明确列出为 open 状态**（P15 前阻塞项）

### 冒烟测试场景

验收时必须手动执行以下场景：

#### 场景 F — 面板折叠恢复 (Panel Collapse Restore)

1. 打开一个包含属性表数据的项目
2. 在属性表中执行搜索并滚动到某个位置
3. 在右侧面板修改某个图层的样式（草稿状态，未应用）
4. 收起属性表和右侧面板
5. 展开属性表和右侧面板
6. **验证**：搜索条件保持、滚动位置保持、样式草稿仍在（未被自动应用）

#### 场景 L — 通过新 UI 完成已有编辑流程 (Existing Edit via New Chrome)

1. 通过新菜单"数据 → 添加数据"打开 GeoJSON 文件
2. 通过新菜单"图层"或右键选择图层设为可编辑
3. 通过新工具栏或菜单进入绘制工具
4. 绘制一个 Polygon
5. 通过工具栏或菜单进入修改工具，修改节点
6. 在属性表中修改该 Feature 的属性
7. 通过菜单"编辑 → 撤销"执行 Undo
8. 通过菜单"编辑 → 重做"执行 Redo
9. 通过菜单"项目 → 保存"保存项目
10. 通过菜单"数据 → 导出图层"导出 GeoJSON
11. **验证**：所有操作均可通过新 UI 完成，结果正确

## 附录：验收原则

1. **验收独立于开发**：验收人应独立验证，不依赖开发者口头确认。
2. **证据优先**：所有 PASS 结果必须有可追溯的证据（commit SHA、测试记录、截图等）。
3. **债务透明**：已知债务（如 OGC fixtures）必须明确记录，不得隐瞒或淡化。
4. **不向后继承**：验收结果绑定到具体 SHA，后续改动需重新验证受影响部分。
