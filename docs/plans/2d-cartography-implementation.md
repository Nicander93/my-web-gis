## 代码基线与边界

- 起点：`ui/visual-alignment-core`，`11ab46b57028a0887aecbd0e3f098015d0c4ed17`，工作区干净。

## 后续接入检查点

源码初查确认下列边界需要同时处理：

- `gis-core/src/project.ts` 当前只读取项目版本 1，并已经有最早期简单样式迁移。增加版本时应覆盖旧项目与现有场景 JSON/ZIP 路径，加载只迁移内存副本，首次保存才写新格式。
- `Layer.style`、`SetLayerStyleCommand`、项目 Store、`ol-runtime/src/layer/style.ts` 和图例共同使用旧契约。迁移须作为同一个完整工作单元，不能只修改类型或只接通地图。
- 分类缺失值/fallback 与分级的 `<=` 边界需要按现有编译行为写回归；直接换成 `step` 容易改变语义。
- `StylePanel`、`LabelPanel`、`Inspector`、`StyleDraftDialog`、场景替换、字段编辑和项目 Store 均引用样式草稿。即时编辑必须替换整条生命周期，不能仅删除“应用”按钮。
- 保存已有内容版本与异步文件写入保护；样式事务应在截取保存快照前收尾，保存期间的新编辑不能误标为已保存。
- 补充包已导入 `docs/design/` 与 `docs/prototypes/2d-cartography/`，含三份 HTML 和十一张参考截图。包内根 README 另存为 `docs/design/2d-cartography-delivery-README.md`，保留仓库原有 README。
- V4 主面板与线符号双栏结构按已认可基线实施；符号库选择器仍供评审。标注高级编辑、完整符号管理器、点/面详细编辑器、发布向导和 SLD 报告没有单独原型，后续按设计原则逐项实现和评审。

## 验证记录

2026-10-21：`ol-style` 45 项单测、包构建、Desktop 默认构建、独立 Spike 构建、Playwright 专测 1 项均通过。默认产品产物不包含 Spike 页面或资源；冻结锁文件检查通过。五组截图、Canvas 语义数据和性能样本已归档至[验收报告](../design/2d-cartography-p0/README.md)。

P0 当时结论：可以继续 P1 契约和迁移，暂不切换生产渲染。后续生产接入与 P2–P5 的实际结果如下；P0 数字不代表产品连续编辑性能。

### P1：工程与场景契约

2026-10-21：工程版本升级至 2。版本 1 只在内存迁移，打开后提示首次保存会写新版；版本 2 必须携带完整合法的标准绘制层与 GIS 图层绑定。旧 `Layer.style` 暂时作为现有编辑控件的兼容缓存；标准层为地图与图例的内容来源。相同数据集共用 source，GIS 图层的子绘制层保持独立，实际复用同一个 OL VectorSource。

- 标准绘制层、绑定和表达式经工程 JSON、场景 JSON、场景 ZIP 保存；场景通过必需扩展 `org.my-web-gis.cartography` v1 明确客户端支持要求。二维与三维混合工程均可保留该扩展。
- 增删图层、递归删除组、数据集重绑、场景控制器事务、场景合并的冲突 ID 修复均同步绘制层。Undo 恢复原始 AST，保留其他图层后来产生的改动。
- 字段重命名只改静态 `get`/`has` 和旧式 filter 的字段操作数，不替换显示文字或 `literal` 内容。删除仍被高级表达式引用的字段会在写数据前拒绝；可识别的旧三模式样式继续按原字段清理规则处理。
- MapLibre `to-string` 对数组/对象采用 JSON 文本，旧实现为 JavaScript `String(value)`；迁移 metadata 与诊断保留这一差异。声明过的标注 zoom 现在生效，旧编译器原先未执行该限制。动态/非字面符号的图例明确提示无法用固定色块表示。
- 标准层变化当前要求重新准备原生 Layer，Source 及要素仍由宿主管理。P2 连续编辑性能和资源异步生命周期继续验证；不把 P0 性能值套用到产品编辑过程。

验证：`ol-style` 55 项、`gis-core` 83 项、`scene-schema` 27 项、`scene-core` 43 项、`ol-scene-runtime` 42 项、`cesium-scene-runtime` 39 项测试通过；Desktop 专项 17 文件/102 项通过。Desktop 与 Viewer 构建通过。生产 Desktop Playwright 独立服务专测 1 项通过，核对标准表达式与旧缓存故意不同的实际样式函数、共享 Source、节点删除撤销和保存重开。该测试使用浏览器运行时行为断言，没有像素相似度或原生 Tauri 验收结论。

### P2：即时编辑与历史

- 基础样式与标注面板使用 Ant Design，输入直接更新 Project 标准层和地图，去掉应用/重置按钮及样式草稿确认弹窗。分类、分级列表保留已选项参数和图例名称编辑；重新分类作为独立操作。
- 连续输入携带当前图层/属性/手势 ID；统一历史将同一手势合为一条命令。保存、切换检查器目标、关闭面板、撤销/重做、原生关闭请求均结束合并。Session 不再保存样式副本，分类参数仅为面板操作参数。
- 标准层命令精确保留 AST，兼容样式命令同时维护旧控件缓存。无法由基础控件无损重建的标准片段显示只读；规则、复合符号、Zoom 表达式和高级 JSON 入口继续由 P3 实现，不宣称 V4 的全部高级能力已完成。
- 完整属性窗口仍保留其独立的应用/取消语义与已有关闭保护。未知高级样式在该窗口的旧式样式/标注页同样只读；仅预览显示属性不覆盖标准样式函数。

验证：GIS Core 88 项测试、受影响依赖链构建、Desktop 类型检查与构建通过。移除草稿后的字段、场景、导入、Store 专测 33 项通过；P2 当时完整 Desktop 回归 65 文件、350 项通过，5 项既有跳过。隔离浏览器组当时 5 项全部通过：20 次输入合并一条撤销、焦点内保存与保存后分离手势、切换检查器目标、未知 AST 只读保留、共享 Source/节点删除撤销/保存重开、分类/分级/标注与真实 OL 样式和图例同步。最终扩大后的回归数字见下文。

### P3：规则、专业符号和项目资源

- 主面板提供规则渲染入口；标准子层可新增、显隐、排序、复制、删除，并按 ID 打开专业编辑器。两栏编辑器支持线/点/面/注记组合、过滤、Zoom 范围、固定/字段/Zoom 线宽、文字与 halo。可视化控件不识别的合法表达式保留原 AST，通过 JSON 入口编辑。
- 内置 9 个 CC0 示例符号，记录来源、许可和用途，不宣称行业规范认证。选择器、管理器分离，支持搜索、收藏、最近使用、个人预设、批量导入导出/删除和自定义色带。使用预设时拷贝定义及资源到项目。
- SVG/PNG/WOFF2 使用 SHA-256 稳定 ID、内嵌数据及来源许可；4 MiB 单资源、24 MiB 项目总量、256 个资源上限。SVG 拒绝脚本、外部引用和递归膨胀；PNG 校验结构、CRC 和像素数据；字体在 FontFace 解码成功后安装。导入、ZIP 和场景合并验证哈希并去重。
- 实际 OL renderer 生成预览；项目图片通过受控内存 sprite 响应，不向虚拟地址发送 HTTP；资源更新/销毁释放所属字体和异步资源。保存重开验证 SVG 和 WOFF2。

### P4：SLD 1.0 和兼容性报告

- 单向输出点/线/面/基本文字、复合道路、常用布尔比较、分类分级、比例尺范围、图片和面图案。旧式 filter 先经标准转换，未支持算子明确报告。连续 Zoom 必须指定固定预览值并接受有损处理；未知表达式在严格模式下不生成 XML。
- 报告包含 JSON 路径、级别、原因和可用替代建议。目标几何字段、数值字段类型显式确认；MapLibre 512 世界瓦片和 OGC 0.28 mm 像素是假设，不承诺 Zoom 与真实比例尺普适等价。
- 离线导出 XML 或 ZIP；ZIP 含 style.sld、按哈希命名的平铺图片、资源许可和兼容性 manifest。实际 GeoServer 的 ZIP 图片位于根目录才能可靠加载，已以真实图像颜色断言验证。
- 固定 GeoServer 2.28.2：双层道路、河流、边界、虚线、标注 halo、SVG、面图案、迁移分类、迁移分级、固定 Zoom、字段线宽共 11 例通过上传/回读/关联/GetMap/GetLegendGraphic。证据见[服务端验收目录](../design/2d-cartography-geoserver/)。

### P5：GeoServer 发布和凭据

- 连接发现 Workspace/Datastore/已有 FeatureType，预检字段、CRS、范围和资源；发布数据仍是独立工作，不伪造创建 FeatureType。项目只保存连接和发布关联引用。Basic/Bearer 内容保留于会话或用户明确选择的 OS 凭据库。
- 浏览器 fetch 与 Rust HTTP 使用独立 transport，原生请求可取消、拒绝重定向、限制响应体。失败的变更请求不自动重试；地址切换使旧请求和凭据引用失效，transport 在读取凭据之前拒绝跨 origin。
- 发布前核对远端样式哈希及图层配置，关联前再次核对图层。服务器支持 ETag 时使用 If-Match；当前实际 GeoServer 无 ETag，已有样式保留并创建随机不可变新版本，回写实际版本名。上传后解析 XML 回读比对、关联回读、PNG 验证，日志定位失败步骤。仅清理本次确认未关联的新样式，不回滚他人配置。
- GeoServer 标准 REST 的图层 GET/PUT 没有事务或 CAS：最后一次检查与关联写入间仍存在极窄并发窗口；只更新 defaultStyle，不宣称跨请求原子性。多人同时改同一图层时需外部协调。旧 SLD 内容不因该窗口被覆盖。
- 浏览器向导已在真实服务上通过 Node 路由桥接验证（解决实验实例 CORS）；独立 Rust HTTP 6 项测试与 cargo check 通过，Windows 凭据实时存取/删除及独立进程重读通过。未执行原生 Tauri 发布向导的人工端到端操作。

## P6：可选发布和浏览后端（2026-10-22）

用户继续授权实现 P6；沿用当前分支及 P1–P5 内容。详见 [P6 能力矩阵、实测及启用决策](../design/2d-cartography-p6/README.md)。

- 发布向导默认 SLD。连接后只读 version/manifest，只有 GeoServer 与 `gs-mbstyle-*` 扩展版本明确匹配时才出现 MBStyle。GeoTools 模块不参与该版本比较；探测不写服务数据。
- MBStyle 保守导出标准点/线/面/基本文字字面量和常用过滤，源绑定由目标 FeatureType 提供，差异报告明确呈现。未知表达式、类型守卫和图片/图案资源严格拒绝，不删除 guard 或临时外链后勉强发布。当前不承诺任意 MapLibre JSON 都可发布。
- 两种格式复用发布日志、不可变新版本、远端哈希/图层冲突检查、关联回读、WMS/legend 和凭据保护。MBStyle 通过无扩展样式 URL 加原生 MIME 读回 JSON；`.json` 元数据端点不能用来校验样式内容。项目 PublishedStyleLink 记录实际格式。
- Viewer 二维标题区增加 Canvas/WebGL 显式选择（`renderer=webgl`，重载页面，不写场景）；对兼容标准点线面使用平行 WebGLVectorLayer 适配器。复杂样式、节点过滤及交互图层整体保持 Canvas 并报告原因，Desktop 编辑地图保持 Canvas。
- GPU 上下文及必要扩展不足时回退；实际 `WEBGL_lose_context` 丢失后切回已准备的 Canvas，Viewer 状态同步显示。宿主 Source 共享且不被 GPU 销毁释放；标准文档和 AST 不改写。
- 实测 Chromium 使用 SwiftShader 软件 WebGL，1 万/5 万点样本中 WebGL 更慢。因此未启用自动后端选择；不将其当作实体显卡或原生 Tauri 性能证据。配对图像和首帧/热帧数据保留为兼容及性能基线。

真实 GeoServer 2.28.2 安装精确匹配扩展后，迁移圆点和线两例通过上传、原生 JSON 哈希回读、关联、GetMap/GetLegendGraphic；解码图像检测到 5,439 / 20,251 个预期颜色像素。分类 `typeof` 负例严格拒绝且未发布。原子性的服务端限制仍与 P5 相同，没有因新增格式而消失。

P6 最终验证：8 个包共 517 项、Desktop 384 项单测通过（合计 901 项，6 项既有条件跳过）；制图工作流 11 项、Viewer 历史工作流 5 项、WebGL 工作流 2 项通过。依赖链、Desktop、Viewer 类型检查与构建通过。实验缓存从测试输出目录迁移到 `.cache/cartography-geoserver/`；恢复字体库后，在新实例复核 SLD 11 例和 MBStyle 2 例均通过。原生 Tauri 人工操作、实体显卡性能及主观视觉签收仍未替代性宣称完成；改动仍未提交或推送。

## 功能基线提交（2026-10-22）

按用户要求，将当前实现提交为功能基线。用户指出界面与专业编辑体验仍需明显改进；上述功能测试不代表产品体验或 UI/UX 已签收，后续单独进行产品化迭代。
