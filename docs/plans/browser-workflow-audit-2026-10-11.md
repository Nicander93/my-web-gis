## A：SHP ZIP（基线 `689c23a`）

使用可重新生成的 `projected-chinese-multi.zip`，三个源图层带 EPSG:3857 PRJ、UTF-8 CPG、中文字段和值。实际 UI 取消全选（确认入口禁用），只勾选 stations 和 sites，预览后确认；工程仅得到两个图层和三条要素，未导入 excluded。表格显示“编号／名称”“01／北京站”；数据中的经纬度及源坐标系信息正确，地图全图后所有原生要素落在可见视口内。

验收发现 shpjs 转换时消费 PRJ，但返回集合不包含 PRJ 元数据，原逻辑因此错误提示文件缺失。vector-io 现在只额外解压 PRJ 条目并保留原文；无效定义拒绝导入，缺失定义仍明确警告。EPSG 代码只读取根 CRS authority，不把嵌套的椭球或单位编号当作坐标系。兼容入口复用多图层解析，保留警告；Desktop 保存原始 WKT 或 EPSG 来源，不重复转换 shpjs 输出的经纬度。

验证：vector-io 构建和 49 项测试通过；Desktop 构建和 209 项测试通过、5 项跳过。`file-import.e2e.ts` 的 A 流程在 1440×900、1024×680、1920×1080 三种窗口均通过，检查紧凑窗口截图。

限制：测试阻断公网瓦片，不以截图证明底图网络定位；地理位置通过独立构造的投影坐标、转换后的经纬度及实际运行时可见位置核对。未运行原生文件选择窗口。

## B：CSV（基线 `dffe039`）

实际上传 `coordinates-with-errors.csv`，自动选择 longitude／latitude，预览明确显示全部 6、可导入 4、错误 2，以及越界纬度和非数字坐标原因。将 Y 改为 longitude 时确认禁用，恢复 latitude 后确认。最终导入预览保留“跳过 2 行无效记录”警告；工程和属性表均只有 4 条有效记录，排除两条错误记录，保留字符串 ID 001／002／004／006、中文、引号内逗号及多行备注。测试兼容检出文件的 LF／CRLF，产品保留原始换行。

没有修改产品逻辑。新增浏览器回归用例在三个窗口尺寸全部通过，并检查紧凑窗口截图；本项不重复构建无变化的产品代码。

## C：GeoJSON／DXF（基线 `0ac7a53`）

GeoJSON 实际上传无效 JSON，提示错误且没有插入图层，随后在同一对话框重新上传 `features-with-issues.geojson`。确认前显示重复 ID 警告；导入后五条要素的内部 ID 各不相同，两个相同源 ID 的属性仍保留，缺失字段和 null 属性未被覆盖，表格可正常展示。

DXF 上传 `basic-entities.dxf`，经过坐标系配置和 CAD 图层选择；取消全选后导入禁用，选择 EPSG:3857 和 Geometry 后预览明确显示两个曲线以 64 段近似及精度损失。五种实体均进入表格；POINT 原始米制坐标转换结果及源 CRS 正确。另上传最小 POINT＋带 bulge 的 LWPOLYLINE 样本，确认前明确提示跳过后者，最终仅导入 POINT。没有修改产品逻辑，三条流程在三个窗口下共 9 项通过；本项不承诺所有 DXF 实体支持。

## D：专题样式（基线 `a42fca1`）

使用 points.geojson，实际 UI 分类 name 并把北京符号设为红色：应用前地图符号和图例不改变，应用后地图原生 StyleFunction 和图例一起改变，撤销／重做恢复对应状态。继续按 value 生成三段分级，检查三个不同原生符号、图例及历史。没有未应用修改时，面板跟随历史；有草稿时撤销不覆盖草稿，明确重置后才恢复当前已应用配置。

验收发现样式工厂产生 `label: undefined`，清空断点标签也会留下 undefined。SceneDocument 只接受普通 JSON，原路径在构造文档时抛错，导致图例变了但地图没变，应用状态也没有收尾。Desktop 在构造文档的样式边界递归省略未设置的可选字段，保留协议对 NaN 等无效值的拒绝。检查器监听实际样式变化，session 仅刷新干净草稿，保留未应用草稿。

Desktop 构建通过；211 项单元测试通过、5 项跳过。上述完整交互在三种窗口尺寸通过，检查紧凑窗口地图符号和图例截图。验收使用独立临时 Vite 端口，避免开发服务器热更新后的模块实例干扰；临时配置不提交。

F、G、J 保持待验证，原生文件选择窗口和公网底图仍未签收。
