# WebView 一体化标题栏实施计划

日期：2026-10-18。状态：T1–T3 已实现；T4 浏览器与单测可自动验收，原生窗口仍需跑 `test:native-titlebar` 并做实机目视。

## 目标与范围

Windows 桌面端将 Logo、文件／窗口／设置／帮助菜单、项目状态和窗口按钮放在最顶部同一行，移除独立系统标题行。WebView 绘制整条顶栏，窗口操作通过 Tauri API 执行。

```text
Logo my-web-gis │ 文件 窗口 设置 帮助 │ 拖动空白区 │ 项目名 · 类型 · 未保存 │ — □ ×
地图  编辑  数据  分析                                           撤销 重做 保存
当前功能区工具……
```

- 二维、三维、项目起始页共用顶栏。浏览器继续显示应用栏，不显示桌面窗口按钮，不调用窗口 API。
- 复用当前菜单命令、项目保存和状态来源；通用交互使用 Ant Design，颜色沿用语义 Token。
- 不新增 GIS 能力，不改变项目协议、历史记录和绘图行为，不同时重构其他面板。
- 首期针对 Windows；不将本次实现声明为 macOS、Linux 已适配。
- 窗口按钮为 WebView 控件，不宣称已完整复刻 Windows 原生标题栏行为。

## 布局与交互约定

- 顶栏初始高度 36 CSS px，作为建议值；若后续调整，同步更新明确的几何断言。其他 Ribbon 尺寸保持原规范。
- Logo、菜单、窗口按钮不收缩；项目名称可省略，悬停可查看全名。1024px 最小支持宽度仍保留菜单和足够的拖动区域。
- 只在明确的空白／非交互区域启用拖动，交互控件及其图标不继承拖动行为。
- 空白区支持左键拖动、双击最大化／还原；系统快捷键及任务栏窗口操作纳入原生验证。
- 最大化图标、可访问名称与实际窗口状态一致；支持从系统侧改变窗口状态后同步，组件卸载不遗留监听。
- 菜单打开后移入相邻入口可切换；未打开菜单时单纯悬停不弹出。
- 键盘支持进入菜单、方向键导航、Enter／Space 执行、Esc 逐级关闭和回焦；输入框、输入法组合态和 GIS 快捷键不被误拦截。
- 采用 AntD Dropdown/Menu 等能力时保留业务动作包装；不为套组件而重写业务命令。现有混合内容按实际菜单结构迁移，不能只增加 ARIA 标签声称完成键盘支持。
- 自动化以行为、状态和必要的 DOM 几何断言验收；用户负责视觉细节审查，不制作逐像素截图对照。

## 关闭保护的约束

1. 原生关闭请求是统一入口；不能仅保护标题栏按钮而漏掉 Alt+F4。
2. 审查二维／三维 dirty 和属性编辑、图层样式等活动草稿的现有约定，复用既有处理，不仅检查一个 dirty 布尔值。
3. 提供保存并关闭、放弃更改、取消。活动草稿需要先按既定规则处理；保存不接受时停留在项目中并给出原因。
4. 保存确认成功后才允许关闭；失败、取消或保存期间发生更新时保留窗口和状态。异步保存完成后重新核对 dirty／版本。
5. 有限的“已允许关闭”状态避免二次触发关闭确认；保存进行时合并重复请求；监听注册与卸载、开发模式重复挂载须正确。
6. 浏览器继续使用现有卸载保护；不把浏览器下载发起等同于原生持久化保存成功。系统强制终止等不承诺可拦截，仍依赖已有恢复机制。

## 验证矩阵

| 类型 | 重点场景 |
| --- | --- |
| 窗口接口单测 | 最大化状态同步、监听清理、错误反馈；关闭确认与保存成功／失败／取消／并发更新、重复请求 |
| 浏览器行为 E2E | 起始页和二维／三维布局；无桌面按钮；Logo 加载；菜单切换、键盘、回焦；真实导入／编辑／保存入口保持可达 |
| 布局断言 | 1024×680、1366×768、1440×900、1920×1080；长项目名、未保存标记；不覆盖菜单和窗口按钮；弹层不被顶栏裁切 |
| 原生 Tauri | 最小化、最大化／还原、拖动、双击、四边／四角缩放；标题按钮／Alt+F4／任务栏关闭保护；弹窗焦点、系统操作后的状态同步 |
| Windows 专项 | 最大化工作区边界、贴边吸附、Win+方向键、最大化后拖动还原、Alt+Space；真实 OS 100%／125%／150% 缩放及跨屏，缺设备则列为未验证 |
| 回归 | 顶栏操作不改变项目 dirty／Undo；菜单快捷键不抢文本输入及绘图会话；二维／三维切换无重复监听和菜单残留 |

浏览器模拟原生 API 只能验证前端调用与分支；受控 deviceScaleFactor 只能验证 WebView 布局，均不能证明 Windows 操作通过。每阶段只运行与改动相关的检查，交付时汇总一次必要回归，不反复全量执行无关测试。

## Windows 11 Snap Layout 的决策点

贴边吸附／Win+方向键与“悬停最大化按钮显示系统布局面板”分别验收。普通 WebView 最大化按钮不保证自动获得系统悬停面板。

- T0 核查现有窗口库是否支持可复用方案；T4 实机验证。
- 不通过时记录为明确缺口，先评估最小 Windows 命中区域适配的代价，再与用户决定是否实施。不得偷偷扩大为完整原生标题栏重构，也不以自制布局弹层冒充系统能力。
- 标准窗口拖动、缩放、最大化、关闭保护属于必需项；无法稳定支持时不得标记整项完成。

## 实施记录（2026-10-18）

- T1：`decorations: false`，顶栏一行，浏览器不渲染窗口按钮；拖动区仅 `window-context`。

- T3：菜单打开后悬停切换；方向键、Esc、命令执行后回焦；输入框和对话框不拦截。设置菜单改为分组列表，图层／编辑项按当前能力禁用。

## 关闭保护修复（2026-10-19）
