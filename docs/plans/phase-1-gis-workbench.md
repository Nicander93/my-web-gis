# 第一阶段执行计划：数据接入、专题制图与 GIS 工作台

> 状态：待执行。本文只制定计划，不代表功能已完成。  
> 制定日期：2026-09-28。执行前必须重新核对工作区。

## 1. 已确认的目标与优先级

阶段目标：用户能够添加常见地理文件或地图服务，管理图层，查看、筛选和选择要素，配置专题样式与标注，保存并恢复项目，导出所需数据。同时交付一个可脱离桌面应用使用、达到 npm 发布条件的 OpenLayers 样式包。

用户已确认：

- 地图引擎继续使用 OpenLayers；桌面界面使用现有 React、Zustand、Tauri 技术栈。
- 优先完善 GeoJSON、Shapefile ZIP、CSV，同时本阶段支持 DXF、WMS、WMTS、WFS 添加图层。
- 顶部采用紧凑菜单栏与固定工具栏，替换当前 Ribbon 页签式入口。
- 左侧图层、中央地图、右侧设置、底部属性表。所有辅助面板支持收起、恢复和调整尺寸。
- 默认展开左右面板，属性表按需打开。记住用户布局，不覆盖已有有效布局偏好。
- 收起面板保留操作上下文；功能入口能展开对应面板；普通地图点击不强制展开用户已收起的面板。
- 提供专注地图模式与重置布局。布局操作不进入项目文件、Dirty 或编辑历史。
- 通用能力按实际职责组织；优先交付样式包，数据能力复用现有 vector-io，不新建无边界的 ol-utils。

以下是计划采用的实施默认值，可在有明确技术证据时小幅调整并记录原因，不需要为常规实现选择反复询问用户：

- 矢量数据统一进入现有 FeatureStore；默认以 EPSG:4326 存储几何，地图显示默认 EPSG:3857，转换只在清晰边界发生。
- 首批支持的输入 CRS 为 EPSG:4326、EPSG:3857，以及通过投影库可解析的明确 PRJ/用户 CRS 定义。不承诺支持所有 EPSG 编号。
- 分类样式、等间距分级、分位数分级、字段标注、由实际样式生成的图例属于本阶段。
- WFS 采用用户明确触发的有界加载和刷新；结果为本地快照，默认只读，允许复制为可编辑本地图层；不回写服务器。
- 导出支持矢量 GeoJSON，以及属性 CSV。已有其他导出 API 保持兼容，但不扩展为完整格式互转工具。
- 分析工具箱、空间连接、字段计算器、栅格分析、三维、插件市场、多人协作不进入本阶段。
- 交付本地 npm tarball 和独立消费验证。本计划不自动执行 npm publish 或网站部署。

本计划记录了本次用户确认的新阶段范围。旧 V0.1 文档中的“仅 GeoJSON”“Vue/Pinia”“不做 Shapefile/服务”等条目不再用于限制本阶段；仍遵守领域与运行时分离、最小实现、不提前建设通用框架等工程规则。不要顺手重写整套旧规范。

## 4. 共同的数据与交互规则

### 4.1 避免错误耦合

- 领域数据不包含 `ol.Map`、`ol.Feature`、DOM、React 或 Tauri 对象。
- UI 调用 command/service；OpenLayers 交互由 runtime 管理。
- 文件选择、认证、网络请求属于应用服务；解析与转换尽量为可测试的独立函数。
- Dataset 与 Layer 继续分离。服务图层不能通过创建空矢量 Dataset 伪装成可编辑图层。
- 布局、面板草稿、任务进度与选择状态不写入项目文件；已应用的样式、图层过滤规则、数据和服务配置需要保存。
- 收起面板保留未应用草稿，但草稿不因收起或切换图层而自动应用。按图层 ID 保存会话状态，删除图层或替换项目时清理。

### 4.2 筛选、选择、导出的统一语义

- 全图层要素为 A；按持久化字段条件过滤后的集合为 F；所选集合为 S。
- 图层过滤同时作用于地图与属性表。改变过滤时将选择收敛为 `S ∩ F`，并显示变化后的数量。
- 属性表的“仅选中”是查看方式，不修改 F；S 为空时显示空结果和清除该查看模式的入口，不偷偷回到全部。
- 属性表文本搜索只筛表格，清楚标记为“表内搜索”，不修改地图过滤与选择。
- 明确提供“选择匹配记录”动作，不把筛选自动当作选择。
- 导出对话框明确区分全部、图层筛选结果、当前选中、当前表格结果，并显示数量；选择导出集合后使用同一快照执行。
- 排序、分页、过滤都通过稳定 Feature ID 保持地图与表格联动，禁止拿行号当 ID。
- 第一阶段字段过滤采用 AND 条件，支持等于、不等于、包含、大小比较、为空；不实现任意 JavaScript、SQL 或 eval。

### 4.3 加载与失败

- 用户在确认导入前看到预览、CRS、有效/无效数量与警告。GeoJSON 简单文件可以走快速确认。
- 严重结构错误终止导入；部分无效记录由用户明确选择跳过。取消不留下半成品 Dataset/Layer。
- 多图层导入按选中数据集分别生成图层，确认时一次提交；不在解析过程中逐条修改项目。
- 加载期间可取消。无法真正中断的本地解析至少做到取消后结果不入库，不声称工作已停止。
- 图层显示 loading/error/ready、重试与错误详情。旧请求不能覆盖新项目、新图层配置或删除后的图层。
- 状态栏放简短状态，详细错误保存在本次会话的任务记录中；日志和项目文件不包含认证秘密。

### B. 常见文件导入

#### P03 — 统一导入流程与二进制文件通道

- 前置：P02。
- 修改：services/files、project.commands、新增 `features/add-data/`；原生文件命令按需修改。
- 实施：添加数据对话框分“文件 / 地图服务”；先完整接通现有 GeoJSON，服务入口待后续任务接通。读文件返回文本或字节，不将 ZIP 当文本。
- 导入阶段为选取→解析/预览→确认→提交。多个图层结果用明确的数组返回；复用现有 VectorImportResult 时以兼容新增接口实现，不直接破坏公共导出。
- 本地文件选择和拖入共用流程；错误、取消、busy、重复点击、项目切换有一致处理。
- 检查：GeoJSON 成功/失败/取消测试；浏览器与 Tauri 二进制读写样本；Desktop build，Rust 变更时 cargo check。
- 验收：原项目不因取消、解析失败、晚到结果受影响；成功导入后激活并定位新图层。

#### P04 — 坐标与属性规范化

- 前置：P03。
- 修改：vector-io 的转换边界、Desktop 导入服务、gis-core GeoJSON 转换测试。
- 实施：明确解析器输出 CRS；原始 CRS 保留为来源元信息。对已转换到 4326 的 shpjs 结果不得二次转换。
- 未知 CRS 要求用户选择支持项或输入可解析定义；无法转换则不添加，不默认把 CAD 米制坐标当经纬度。
- 为缺失/重复 ID 生成稳定的当前导入 ID，保留原 ID 为来源信息且避免覆盖原属性。空几何及当前领域不支持的 GeometryCollection 明确报告，禁止静默漏掉。
- 验收：3857 点转换后位置正确；已是 4326 的数据不漂移；未知投影有可处理提示；重复 ID 不导致选择串行。
- 检查：固定控制点、空几何、非有限坐标和属性类型测试。坐标容差按样本单位定义。

#### P05 — Shapefile ZIP

- 前置：P04。
- 修改：vector-io/shapefile.ts、types.ts、导入对话框与测试。
- 实施：ZIP 内多份 Shapefile 显示为可选列表，分别导入，不再强制合并新流程；保留旧 importShapefile 的兼容行为或明确版本迁移。
- 识别 .prj/.cpg；提供编码覆盖入口。实际解析库不支持覆盖时，通过正确解析路径补齐，不能显示无效设置。
- 验收：中文字段正常；两份 SHP 可选其一或全部；缺少必要文件、无效 ZIP、缺失投影均有明确结果；保存再打开数据仍在。
- 检查：真实小 ZIP fixtures 的要素数、属性、位置、警告；Desktop build。

#### P06 — CSV 坐标点

- 前置：P04、P05。
- 修改：vector-io 新增 CSV 解析能力、导入预览。
- 实施：使用可靠 CSV 解析器，支持 UTF-8 BOM、可选编码、逗号/分号/Tab、引号及字段内换行；不使用 split(',')。
- 用户选择 X/Y 字段、输入 CRS；默认属性保留文本以保护前导零，坐标字段单独严格解析；数字属性提供明确转换选择。
- 展示总记录、可导入数、错误行与原因；确认跳过无效行后生成点图层。无坐标的普通表格本阶段不作为空间图层导入。
- 检查：前导零、中文、转义引号、空行、无效数字、越界坐标；验收有效记录数与地图位置一致。

#### P07 — 二维 DXF

- 前置：P04、P06。
- 修改：现有 vector-io/dxf.ts、导入配置与测试，不另起解析器。
- 实施：ASCII DXF 按原始 CAD 图层分组可选导入，保存实体 handle/layer 等来源属性；明确源 CRS 与单位。
- 基础范围：POINT、LINE、无 bulge 的 LWPOLYLINE/POLYLINE、CIRCLE、ARC、TEXT/MTEXT 锚点。曲线近似须提示精度；文字只作为带文本属性的点，不承诺还原 CAD 排版。
- 审核现有 SPLINE 控制点连线和 polyline bulge 行为：未正确支持的实体发出警告并跳过，不将错误几何伪装为精确转换。DWG、二进制 DXF、BLOCK/INSERT、HATCH 不在本阶段。
- 验收：位置、单位、图层归属正确；不支持实体列明类型和数量；原始文件不被修改。

### C. 专题制图与公共样式包

#### P08 — 样式包基础与分类算法

- 前置：P07。
- 新增：`packages/ol-style`，暂用工作区名 `@desktop-webgis/ol-style`；实际 npm scope 在发布前确定。
- 包不依赖 Desktop、gis-core、scene-schema、React、Zustand、Tauri；定义自身 JSON 可序列化样式契约。提供不依赖 OL 的 `./classification` 入口和 OL 适配主入口；OL 作为 peerDependency，支持范围只声明已验证版本。
- 第一版契约：single/categorized/graduated、点线面基础符号、字段、分类条目或断点、fallback、可选标注。保持混合几何按类型渲染，不强制一层只有一种几何。
- 算法：等间距、分位数；数值只接受有限 number，不偷偷把空字符串变 0；忽略无效值并返回数量。类别区分数字 1 和字符串 '1'，null/缺失走 fallback。
- 明确区间：首段含最小值，各段上界包含、后续下界不含；去重断点，常量数据只有一段，空数值集返回可解释错误。分位数采用排序后的线性插值，规则写入 API 文档。
- 验收：对固定数组精确断言断点和边界归类；大量重复值不生成空重复图例；颜色数与有效分段一致。

#### P09 — OL 样式编译与桌面接入

- 前置：P08。
- 修改：ol-style、gis-core 样式契约/迁移、ol-runtime/layer/style.ts、Project 序列化。
- 实施：编译为 OL StyleFunction；按配置缓存基础符号，避免每个要素每帧重做分类。标签不得因共享可变 Text 对象而串值，缓存有上限或生命周期清理。
- 领域只引用样式包的纯类型，不导入 OL 实现；将旧简单 LayerStyle 转为 single，旧项目读取后显示保持一致。
- 编辑属性后样式与标注按新属性更新。选择高亮独立叠加，不覆盖保存的专题样式。
- 检查：点/线/面与混合几何、fallback、分类边界、标签空值、编辑后更新、旧项目迁移；Desktop 和相关 package build/test。

#### P10 — 样式、标注面板和图例

- 前置：P09。
- 修改：右侧 Inspector 拆出有明确职责的样式/标注组件；复用右侧容器，不创建嵌套面板框架。
- 实施：模式、字段、分类方法、分段数、色带、分类项编辑、fallback；标注含字段、字号、颜色、描边及缩放范围。支持应用与重置草稿。
- 改草稿不改项目；一次“应用”形成一个可撤销配置操作。重新分类是明确动作；属性编辑自动采用现有断点渲染，不擅自重算所有断点。
- 图例从已应用配置生成，样式与图例共用类别/断点结果；图层列表提供简洁符号预览。
- 验收：换图层/收起恢复保留各自草稿；应用只作用于目标图层；撤销恢复完整样式；保存打开样式、标注一致。

#### P11 — Scene/Viewer 样式一致性

- 前置：P10。
- 修改：scene-schema 的 TS 与 JSON Schema、validate/normalize/parse、scene-core、scene-codegen、ol-scene-runtime；按实际引用修改 style-assistant。
- 实施：新写出 Scene 使用明确的新版本，旧 v1 保持可读；旧单一符号与标签通过迁移/适配进入同一编译器。不能把新字段塞进旧 schema 后假装兼容。
- Desktop 与 Viewer 复用 ol-style，不复制分类、分级和标注实现；协议层只依赖纯类型，不引入 OL 运行时依赖。
- 验收：同一份数据在 Desktop 与 Viewer 分类归属、断点、颜色、标注一致；旧 Scene 示例继续可读；代码生成使用新能力时不静默降级。
- 检查：schema、迁移、codegen、runtime 测试与 Viewer 构建。提交前读现有 Scene 规范并追加必要版本说明。

### D. 属性操作与图层工作流

#### P12 — 字段条件、排序与选择

- 前置：P11。
- 修改：gis-core 新增独立过滤/排序函数、project.store、AttributeTable、ol-runtime 可见要素同步。
- 严格实现 4.2 的集合语义；数值/文本比较规则明确，空值单独处理，排序稳定；仅选中与表内搜索为会话状态。
- 先保留现有分页，避免无证据引入表格框架；新增字段统计至少支持非空/空计数及数值 min/max/sum/mean，标明统计范围。
- 属性编辑后重算相关过滤与统计，隐藏的要素不继续高亮；撤销恢复属性及其派生显示。
- 验收：地图和表格过滤一致；切换页码、排序后选择不串；筛选后选中数量正确；全部为空时统计不出现 NaN。
- 检查：集合语义、边界值、排序、编辑与撤销、地图联动测试和 Desktop build。

#### P13 — 导出范围与复制为本地图层

- 前置：P12。
- 修改：layer/project commands、files 服务、vector-io CSV 写出、导出对话框。
- 实施：GeoJSON 导出几何和属性；属性 CSV 正确转义分隔符/换行/引号；默认处理电子表格公式前缀并在说明中写明。GeoJSON 保留原始字符串。
- 四种范围及数量按 4.2；为筛选/选中结果创建独立本地图层，分配独立 Dataset，不能与来源共享可变引用。
- 验收：导出后重新导入要素数和坐标正确；空范围不生成误导文件；复制图层编辑不影响来源；取消导出不改变 Dirty。

#### P14 — 图层上下文菜单与分组

- 前置：P13。
- 修改：LayerPanel、layer.commands、project.store、gis-core 图层/分组保存模型。
- 实施：右键与“更多”按钮访问同一菜单；活动图层、加载状态和选中要素数量有明确视觉状态。菜单包含定位、样式、标注、属性表、过滤、导出、复制、重命名、移除。
- 支持单层分组、组显隐、组内/跨组拖动排序；保留按钮或键盘排序作为替代。暂不做无限嵌套组。
- 分组引用图层 ID，不复制 Dataset。组隐藏保留子图层自身 visible，重新显示恢复原状态；渲染顺序与列表约定保持一致。
- 图层操作根据能力启用；移除图层清理选择、草稿、过滤引用和任务，不能留下可写入已删除数据的旧编辑命令。
- 验收：显隐与顺序往返保存一致；地图层叠符合列表；删除组前明确选择保留子图层还是一起移除。

### E. 地图服务

#### P15 — 服务描述、能力与连接界面

- 前置：P14。
- 修改：gis-core Dataset/Layer 可辨识联合类型、ol-runtime 图层注册分支、Add Data 的服务页、项目读写。
- 实施：明确矢量快照、WMS、WMTS 的描述与能力（查询属性/编辑几何/样式/导出），不通过大量类型断言把服务当 VectorLayer。
- URL 规范化保留已有查询参数；capabilities 解析与 fetch 分开；支持超时、取消、认证错误、协议异常、非 XML/错误 HTML 提示。
- 初始认证支持无认证、查询 token、Bearer header；持久化只保存 credential 引用。查询 token 从可分享 URL 分离；设备认证采用平台安全存储，浏览器无法安全持久化时会话输入。禁止把 token 写入 fixture、日志或 Scene。
- 浏览器遇到 CORS 明确说明；Tauri 有需要时使用最小原生请求通道并验证权限；不引入公共代理或关闭 TLS 验证。
- 服务描述变更需使旧请求失效；首次连通不把整个远程目录写入项目。
- 验收：旧项目仍能打开；服务图层不可误进几何编辑或矢量导出；失败连接不生成空图层。

#### P16 — WMS 添加图层

- 前置：P15。
- 实施：支持 WMS 1.3.0 和 1.1.1 capabilities，展示有 Name 的可请求子图层、样式及支持 CRS；用户选择后按子图层添加。
- 优先沿用 OpenLayers 官方 source/format 能力处理版本与坐标轴；兼容 EPSG:4326 轴序差异，以请求参数和图像范围测试确认。
- 支持显隐、透明度、排序、范围定位、保存重开和重试；GetFeatureInfo 不是本阶段必需功能，界面不可假装有矢量属性表。
- 检查：两个版本 capabilities、继承 CRS/extent、服务异常样本、GetMap URL 与请求范围；人工验证一张已知范围地图。

#### P17 — WMTS 添加图层

- 前置：P16。
- 实施：解析 layer/style/format/TileMatrixSet/TileMatrixSetLink，列出兼容项并合理默认；支持 capabilities 声明的 KVP 或 REST 模板。
- 使用真实 tile matrix 的 origin、resolution、matrix ID 和范围；不把所有服务硬编码成 XYZ、固定数字 zoom 或固定 256 像素。
- 不兼容投影或缺少矩阵信息时给出明确解释，不偷偷选其他矩阵。模板与认证凭据分开管理。
- 检查：非数字 matrix ID、不同 tile size、两种请求编码 fixtures；缩放与边缘瓦片位置正确；保存打开仍可加载。

#### P18 — WFS 有界加载

- 前置：P17。
- 实施：首批支持 WFS 2.0.0 和 1.1.0；解析 feature type、默认 CRS 和 advertised output format，优先 GeoJSON，必要时使用受支持的 GML 读取路径。
- 用户选择当前视图范围或明确全范围，并设置上限，默认 5000、可调整至本阶段上限 50000；这是产品保护阈值，不是性能保证。分页仅在服务能力允许时启用，处理版本参数差异。
- 请求坐标轴和 srsName 有样本验证；记录已加载数量、是否完整、来源和查询范围。不把截断结果显示为全部。
- 快照默认只读，支持筛选、专题样式、导出和复制可编辑图层；用户明确刷新才替换快照。刷新失败保留原快照；重复 ID、分页重复有检测。
- 验收：取消、上限截断、后续页失败、删除图层、刷新中切换项目均不污染状态；复制编辑不触发 WFS-T。

### F. 项目闭环、包交付与阶段验收

#### P19 — 项目与 Scene 全链路集成

- 前置：P18。
- 实施：保存包含新样式、标注、分组、过滤、原始 CRS 元信息、服务连接描述。文件导入与 WFS 快照的数据随项目保存，重开不依赖原始文件或 WFS 当时可用。
- WMS/WMTS 重开保留配置并尝试连接；失败显示可重试占位而非丢弃图层；项目支持离线打开其本地部分。
- 补齐新 Scene 版本的 WMS/WMTS、样式、分组所需展示信息和矢量过滤；WFS 发布为明确标识的快照，不默认对外发布动态凭据。
- 检查 scene-codegen、publisher、Viewer 对新协议的处理；不能支持的内容显式阻止输出并说明，不静默省略。只生成静态产物，不上传。
- 将样式应用、标签配置、过滤、分组/排序等本阶段新增持久化操作接入一致的撤销路径；沿用 EditCommand，不引入第二套全局历史。单个滑块拖动合并为一次命令。
- 验收：混合项目保存→关闭→重开，图层数、顺序、位置、样式、标注、过滤正确；断网仍可查看本地数据；布局和凭据不进入可分享内容。

#### P20 — 样式包发布准备

- 前置：P19。
- 实施：审查 ol-style 的 exports、types、files、peerDependencies、sideEffects、许可证、README、变更记录；公开 API 避免暴露应用内部术语和路径。
- 独立示例至少含分类、两种分级、标注和图例。以 `pnpm pack` 产出 tarball，在工作区解析范围外的临时消费项目安装 tarball 和声明的 OL 版本，执行类型检查、构建与示例运行。
- 验收：消费者无需安装任何私有工作区包；dist 无仓库绝对路径或 workspace:* 运行依赖；包入口和类型声明可正常加载。
- 检查 vector-io 是否仍保持已有导出兼容，并记录独立发布所需依赖；本阶段不强制把它也重构成新的数据包。
- 真正发布前才确定 npm 包名/scope、版本、许可证归属、账号与发布意图；不在准备工作开始时阻塞等待这些信息。

#### P21 — 全阶段验收与交接

- 前置：P20。
- 运行根 build/test，记录结果；Tauri 读写与原生服务请求按实际变更验证。性能使用固定数据记录耗时和交互观察，不凭空声称支持海量数据。
- 执行下面所有验收场景，附失败项或截图/记录位置。修复影响核心流程的问题后再标记阶段完成。
- 更新相关 README、支持矩阵、迁移说明与公开包用法。标明未支持 DXF 实体、服务协议限制与真实未验证项。
