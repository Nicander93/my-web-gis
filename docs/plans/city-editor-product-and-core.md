# 城市编辑器：产品交互与核心能力演进

日期：2026-10-03；实现更新：2026-10-04。状态：通用绘制、分组功能区、顶点编辑、结构化属性与字段标注已实现；下一阶段优先场景分组、多选和批量操作，再补分类样式。

## 产品定位

以城市数据整理和编辑为主：加载资源、整理图层与对象、修改位置或几何、配置样式和属性弹窗、保存并交付场景。二维地图与三维场景在创建项目时区分。水面与其他局部特效采用相同的对象管理方式。

工具软件与扩展包同时演进。编辑器通过扩展包完成真实工作流；扩展包也能用于普通 Cesium 项目和独立 Viewer。以 Mars3D 的领域命名和操作方式为参考，保持本项目独立实现与已有包边界。

原 V0.1 架构规范中的“当前不实现 Cesium”描述的是早期二维阶段；当前三维范围依据用户后续要求和已实现的城市三维包。保留领域与运行时分离、命令与历史分离、避免提前复杂抽象等原则。

## 顶部功能区

采用分类页签与分组命令。默认进入“数据”，支持收起、展开并记住布局偏好。项目操作、保存、撤销、重做为共用入口。

| 分类 | 分组与主要操作 |
| --- | --- |
| 场景配置 | 光照：太阳光、阴影、时间；环境与地表：天空、底图、地形；视角与渲染：初始视角、质量 |
| 数据 | 加载：文件、服务；创建：绘制、模型；显示与交互：样式、标注、属性弹窗；管理：属性表、刷新、数据源 |
| 编辑 | 选择、框选；移动、旋转、缩放、精确定位；顶点编辑、吸附；复制、分组、锁定、删除 |
| 特效 | 天气、后处理、局部效果；局部效果包含水面、扫描、流动线、粒子 |
| 分析 | 测量、剖面、通视、裁剪等；按实现进度接入 |
| 视图 | 定位、俯视、收藏视角；面板、分屏、恢复布局 |

首版优先分组功能区；紧凑下拉功能区作为布局备选。上表为规划，不将尚未实现的工具呈现为可用功能。

### 操作归属

- 顶部决定“做什么”，左侧管理“操作谁”，右侧配置“怎么做”，视图提供空间反馈。
- 选中对象只更新属性和工具可用性，不自动切换顶部分类。禁用操作说明原因：未选对象、对象类型不适用、未加载、隐藏或锁定。
- 样式、标注、Popup 入口定位到当前图层或对象的属性区域；无选择时给出选择入口。不要同时打开多个配置浮窗。
- 全局光照、雾和后处理进入场景配置；具有空间范围的水面等进入场景树，支持选择、显隐、定位、删除和撤销。
- 编辑模式点击对象用于选择；预览模式点击对象展示 Popup。预览收起编辑功能区和属性面板，退出后恢复工作区。
- 加载失败保留资源记录与错误状态，允许修复地址后重试；其他对象继续使用。
- 面板尺寸、分类页签、选择、预览、工具切换属于临时状态，不产生项目脏状态或撤销记录。

### 常用工作流

1. 加载数据：选择文件或服务 → 校验 → 场景树显示加载状态 → 成功后选中 → 定位或配置属性；失败时在同一对象上修复。
2. 整理对象：选择 → 显隐、命名、分组、锁定 → 可用工具更新；拖动只预览，完成操作才生成一条编辑命令。
3. 配置 Popup：选择支持属性的对象 → 属性弹窗 → 标题、字段选择和别名 → 查看实际属性预览 → 保存配置 → 发布 Viewer 使用同一配置。
4. 绘制与编辑：进入工具 → 场景中操作 → 完成或取消；取消清理临时对象，完成后选中新对象并支持撤销。

## Mars3D 参考与本项目约定

已核对官方 API 的图层与图形分层、`bindPopup`、`GraphicLayer.startDraw`、`GraphicLayer.startEditing` 和 `TilesetLayer.startEditing`。参考来源：[GraphicLayer](https://mars3d.cn/api/GraphicLayer.html)、[TilesetLayer](https://mars3d.cn/api/TilesetLayer.html)。这些参考确定接口风格，不代表依赖 Mars3D 或承诺接口兼容。

本项目统一以下语义：

- **Layer** 管理一组数据或一种资源的加载、显隐、定位、交互与释放。
- **Graphic** 表示可选择、可配置、可绘制和编辑的空间对象，持有稳定 ID、几何、属性和样式。
- **DrawSession / EditSession** 表示一次交互过程，明确开始、预览、完成、取消与释放。
- **Scene** 组合图层、相机和全局环境；可序列化定义与 Cesium 运行实例分开。
- 核心包返回变化结果；应用层决定写入项目和编辑历史。独立消费者可以自行接入历史。

图层的整体变换编辑与 3D Tiles 内单个构件的选择、属性展示是不同能力。当前只支持资源整体变换，不宣称能编辑建筑网格或回写源瓦片文件。

## 目标 API 形态

下面展示已实现的核心入口；宿主回调自行接入 UI 和历史。保持已有 `LayerCollection` 入口，避免为外观另造一个大型统一 MapEngine。

```ts
const layers = new LayerCollection(viewer)

const city = new TilesetLayer({ id: 'city', url: './city/tileset.json' })
city.bindPopup({ title: '建筑信息', fields: [{ field: 'name', label: '名称' }] })
await city.addTo(layers)

// 已实现：图形层使用同一图层生命周期。
const annotations = new GraphicLayer({ id: 'annotations', name: '标绘' })
await annotations.addTo(layers)

const draw = annotations.startDraw({
  type: 'polygon',
  heightMode: 'ground',
  style: { color: '#3b796a', width: 3 }
})
const result = await draw.result
if (result.status === 'completed') {
  const graphic = annotations.addGraphic(result.graphic)
  graphic.bindPopup({ fields: [{ field: 'name', label: '名称' }] })
  const edit = annotations.startEditing(graphic.id)
  const edited = await edit.result
  if (edited.status === 'completed' && edited.changed) {
    saveGeometryChange(edited.id, edited.before, edited.after)
  }
}
```

`startDraw` 返回包含 `result/finish/cancel` 的会话。结果以 `completed/cancelled` 明确区分；取消是正常用户操作，运行错误才拒绝 Promise。绘制完成返回纯定义，由宿主决定加入图层和保存；命名与 Mars3D 接近，提交边界采用本项目约定。

图形绘制和编辑位于 cesium-layer 内部，GraphicLayer 组合其便利入口；编辑模块仅以类型依赖 Graphic，避免运行时循环。模型编辑继续保留独立 `TilesetEditor`。

### 一致性要求

- 全部空间输入说明坐标和高度语义：WGS84 经度/纬度、椭球高度；局部变换使用 ENU 米和角度。贴地、贴模型、绝对高度必须显式区分。
- 同一场景同一时刻只激活一个交互会话。切换工具、移除对象、销毁、失焦或 Esc 时取消预览，恢复相机和拾取状态。
- 多次鼠标移动不写入历史；一次完成对应一条提交。顶点编辑提交包含修改前后几何，取消恢复原值。
- API 提供类型化事件和取消订阅方法；销毁幂等，迟到的异步结果不能重新挂载资源。
- 配置数据可保存和版本迁移；不序列化 Cesium 实例、DOM、回调或令牌。
- 每个可公开包有明确的职责、peer dependency、独立示例、类型声明、资源部署说明和可复现测试。
- 保留显式的原生 Cesium 出口，用于高层 API 暂未覆盖的能力。

## 实施顺序与验收

### 第一段：通用绘制闭环

先抽离现有绘制逻辑并建立点、线、面会话；明确结束、取消、坐标拾取与临时对象所有权。水面使用面绘制结果生成 WaterNode，普通面图形也使用同一过程。然后补齐 GraphicLayer 与可保存的图形定义，让“数据 → 绘制”成为真实入口。

验收：独立普通 Cesium 页面和 Desktop 都能绘制；取消不新增对象、不产生脏状态；完成一次只生成一条命令；切换工具和销毁不遗留事件与预览资源；保存重开后几何、属性和样式一致。示例不依赖 React、Zustand 或 Tauri。

### 第二段：几何编辑与图层整理

点位置、线面顶点移动/增删、取消恢复和撤销/重做；图层/图形能力查询、选中高亮、Popup 和锁定行为统一。分组、多选和吸附按真实需求逐项加入。

验收：选择、右侧属性与空间反馈同步；不适用的操作有清晰原因；一次拖动一条历史；资源整体编辑与构件属性访问互不混淆。

### 第三段：可视化与发布

先做好实用的统一颜色、按属性分类、标签和高亮，再增加材质、天气、后处理和局部效果。可视化配置由协议保存，编辑器与 Viewer 共用渲染逻辑。

验收：更新样式不重新下载原始数据；离开编辑模式后 Popup 正常工作；发布场景复现配置；连续渲染仅在有活动动态效果时启用；独立消费者打包与使用不依赖工作区源码。

每段完成源码、测试、真实交互验证及消费者示例后再推进下一段。产品界面按能力逐步接入，避免一次性铺满未实现按钮。
