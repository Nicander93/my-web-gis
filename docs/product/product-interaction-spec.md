# Desktop WebGIS 产品功能与交互规范

> 版本：Implementation Baseline 1.0 · 2026-10-13
> 对应原型：`../prototypes/workbench/desktop-webgis-2d-final.html`、`desktop-webgis-3d-final.html`
> 面向：产品、前端、GIS Runtime、测试 Agent
> 状态：**已确定为基准，直接实施；范围有变化须单独记录**

## 0. 决策优先级与用词

- **规范优先级**：本交付包的产品规范、UI/UX 规范和验收标准，优先于两个最终 HTML 原型里的交互和外观；后者优先于 2026-10-13 之前的讨论，再往下是项目内早期的 PRD V0.1。原型里尚未实现的真实运算不算可交付能力。
- **MUST**：本轮必须满足。**SHOULD**：尽量交付，无法交付时要书面说明原因。**LATER**：明确不在本轮范围内。不得用展示性按钮、写死的数值或动画来假装功能已经实现。
- 本轮交付的软件由**二维项目**和**三维项目**组成。两者共用 Shell、窗口系统、命令和项目服务，但**一个项目只属于一种工作区类型**。不做同一项目内的多视图，不做实时二三维联动，也不做二三维之间的自动转换。
- 使用专业但清晰的 GIS 术语。`GraphicLayer` 是可发布的 Cesium API，也是内部的渲染容器，**不是用户必须创建的场景树节点**。

## 1. 主要对象及其关系

| 概念 | 用户看到的意思 | 数据与行为 |
|---|---|---|
| Project | 一份 `.webgis.json` 项目文件 | type 为 `2d` 或 `3d`；保存业务内容，不保存本机的窗口位置和尺寸 |
| Folder | 场景树或图层树里的普通文件夹 | 可以多级嵌套，可以混放各种可组织的对象；有显隐和锁定状态，但不继承样式 |
| 2D Data Layer | 面向数据集的图层 | 一个图层对应多个要素；提供字段、属性表、过滤、样式和编辑能力 |
| 3D Graphic | 独立的标绘对象 | 每个 POI、文字、线、面都有独立的 ID、几何、样式、业务属性和交互配置 |
| 3D Asset Node | 一个 GLB、3D Tiles 或影像等资源 | 引用外部资源，可以单独显示、定位和配置 |
| 3D Tiles Effect | 属于某个 Tileset 的裁剪或压平配置 | 可以启用停用、编辑、重排（适用时）、撤销和持久化；不修改原始瓦片 |
| Selection | 临时的选择状态 | 不会自动打开属性窗口，也不会因为属性表里选中了行就自动定位 |

**不允许**在用户新建文件夹时自动把它转成 GraphicLayer，也不要求用户“先建 GraphicLayer 再画 POI”。500 个独立 POI 就是 500 个可管理的对象；内部可以用共享的 Cesium `GraphicLayer` 或 `CustomDataSource` 渲染，不要求和对象一一对应。

## 2. 桌面工作流和公共交互

### 2.1 启动与项目

1. 启动界面提供 `新建二维地图`、`新建三维场景`、`打开项目`、`最近项目`。最近项目不可用时保留条目，并说明遇到的问题。
2. 打开项目时按保存的类型进入相应工作区。新建、打开、关闭或切换项目之前，先检查是否有未保存的修改。
3. `Ctrl+S` 保存，`Ctrl+Shift+S` 另存为。写入失败不得清除未保存标记。保存路径变化之后，需要重新基准化相对资源路径。
4. 保存内容：数据源及其 CRS、图层与文件夹与对象、属性和样式与变换、二维地图状态或三维相机及效果，以及必要的数据编辑结果。外部凭据不写进项目。
5. `自动恢复草稿` 写入本机独立的恢复缓存，不覆盖正式项目。有修改后按间隔保存（建议约 2 分钟，实施时可配置）。崩溃后重开会提示恢复或舍弃；正常保存成功后清理过期草稿。草稿有大小和保留期限制，写入需要保证原子性。
6. 旧文件、旧版 scene/schema 应当支持迁移，或者明确提示不支持；**不能静默删除未知节点**，也不能覆盖尚未加载完毕的项目。

### 2.2 统一工作区

- 顶部依次是**一行应用菜单**（`文件 / 窗口 / 设置 / 帮助`）、**一行 Ribbon Tab**、**一行 Ribbon 工具**，底部是状态栏。
- 二维 Ribbon 为 `地图 / 编辑 / 数据 / 分析`，三维 Ribbon 为 `场景 / 标绘 / 编辑 / 瓦片 / 分析`；具体命令因能力不同而不同。未支持的命令置为不可用并说明原因，不允许假装执行。
- 地图和 Cesium 视口在 Workspace 里**完整铺底**。停靠窗口和浮动窗口覆盖在画布上，不压缩画布；双击定位仍然落在整个视口的几何中心，不会为了避让侧栏而偏移。
- `窗口`菜单可以切换以下面板：树、检查器、属性表、工具箱、日志、性能与诊断等。关闭后就完全消失，**不在边缘保留固定的恢复按钮**，需要时从窗口菜单重新打开。支持保存布局和重置布局。
- 初始布局：左侧树打开；右侧检查器和底部属性表关闭。底部属性表打开时横跨**整个 Workspace**，包括左右面板下方的区域。
- 停靠窗口和浮动窗口都可以拖动、调整尺寸和关闭。属性对话框可以非模态存在，绑定到固定的对象 ID，不会因为换了选中对象就切换编辑目标。
- 本机记住窗口位置、尺寸、浮动或停靠状态以及可见性；项目文件里**不保存本机的 Docking 布局**。

### 2.3 对象选择与右键

- 在地图或树上**单击选择**；`Ctrl` 切换多选，`Shift` 按顺序范围选择（树和表格都遵循明确的顺序）。选择不需要先进入编辑模式。
- 在树和地图上**双击对象即定位**；双击空白处不触发定位。定位以整个地图视口的中心为准，不因为面板而偏移。
- 右键菜单**随对象类型和上下文变化**：属性、定位、重命名、显示、锁定、移动、复制、删除、重新加载或重新定位资源、属性表（适用时）。只显示当前对象确实支持的动作。
- 在地图上选择会更新树的选中态，但不会强制展开文件夹或滚动树；需要时提供显式的`在树中定位`。
- 检查器如果已经打开，会跟随当前选择，但**选择本身不会打开检查器**；检查器可以固定到某个对象。
- 用 Cesium 拾取到 3D Tiles 的子 Feature 时，检查器可以显示该 Feature 的元数据，树里仍然保持 Tileset 图层选中，并提供`返回图层`。不会把海量 Tileset 内部 Feature 展开到树里。
- 多对象样式编辑只修改用户明确指定的字段，未编辑的字段保持不变；所有批量修改都作为一次可撤销的命令。

### 2.4 Esc、绘制与编辑

| 当前状态 | Esc 的作用 | 提交方式 |
|---|---|---|
| 普通选择 | 关闭上下文菜单或取消临时状态，不清空已有选择 | 单击选择 |
| 连续放置 POI 或文字 | 退出工具，保留已经创建成功的对象 | 每次单击独立提交一个 Graphic |
| 正在绘制线或面 | 丢弃当前未完成的草稿并退出工具 | Enter，或在绘制上下文里右键完成 |
| 拖动已有 POI | 取消本次拖动，回到起点 | 单击新位置提交 |
| 拖动 Gizmo | 撤销正在进行的手势，退出当前编辑工具 | 松手时生成一次编辑命令 |
| 属性窗口里有未应用的值 | 按窗口的取消规则处理，不能误提交 | Apply / OK / Cancel |

- 绘制线或面时，Backspace 回退最后一个控制点；焦点在文本输入框内时，Backspace 必须作为普通的编辑键，不触发 GIS 命令。
- Ctrl+Z / Ctrl+Y（或 Ctrl+Shift+Z）只作用于已提交的命令；单次绘制会话里的 Backspace 不应混进全局撤销栈。
- 切换工具时要清理临时对象、控制柄和事件监听，并正确恢复相机和地图交互。

## 3. 二维工作区（OpenLayers）

### 3.1 图层、数据及 CRS

- 图层树支持自由文件夹多级嵌套，顺序与地图绘制顺序一致；支持显隐、锁定、重命名、拖拽跨目录、搜索和批量操作。
- 加载本地 GeoJSON、Shapefile ZIP、CSV（字段映射）、DXF（坐标系、单位、子图层），以及地图服务 WMS、WMTS、WFS。支持错误提示、重试和服务图层选择。
- 源 CRS 和显示 CRS 是两个不同的字段。文件里有明确的 CRS 就直接读取；无法确定时要求用户输入，不根据经纬度数值去猜。CRS 的**赋值**（修改元数据）和**转换或重投影**（真的改坐标）是两件不同的事，必须用不同的命令，并给出明确提示。
- 切换地图投影不应偷偷改掉已保存数据集的坐标。GIS 数据导入要完整记录源坐标和内部坐标的约定，导出时按用户指定的 CRS 执行。

### 3.2 选择与矢量编辑

- 支持点、线、面选择，高亮、Ctrl/Shift 多选；框选和按表达式筛选属于可扩展的专业选择能力。
- 进入可编辑图层后可以绘制点、线、面，移动顶点、插入顶点、删除顶点，修改几何、删除要素；编辑前检查锁定状态、类型和几何有效性。
- 线面的处理至少明确包含分割、合并选中面、裁剪、缓冲区、差集、相交等。**合并面**是修改原图层的编辑命令，多个要素的属性冲突需要显式处理；不能和生成新图层的“融合/Union”算法混为一谈。
- 数据处理默认**生成新的数据集或图层**；如果要直接修改原数据，必须单独标明，并纳入撤销和确认流程。所有空间处理都要有参数校验、忙碌提示与取消、错误信息、进度和输出范围说明。禁止把静态 SVG 或模拟结果当作算法输出。
- 属性表和字段：一个可停靠、可浮动、可最大化的属性表窗口，多个数据集用 Tab 呈现。打开新图层时新增 Tab；切换 Tab 不清空原有的选择、筛选和排序。
- 支持字段排序、隐藏列、搜索、过滤全部或已选或过滤后的行、字段统计、单元格编辑、批量编辑、字段计算器和字段类型检查；数据量大时考虑虚拟行渲染。
- 点击表格行会选中并高亮地图，**但不会自动移动视图**；双击行头或非编辑单元定位；编辑模式下双击可编辑的单元格进入单元格编辑，避免行为冲突；提供显式的`跳转到选中`。
- 表内联的字段计算器直接修改当前数据集，整体作为一次原子撤销命令；空间处理工具箱里的字段计算可以输出新数据集。两者共用同一套可验证的表达式内核，但语义不同。
- 字段变更必须校验类型和空值约束，计算失败不能留下半成品；属性表要保留字段顺序、滚动位置、排序等每个数据集各自的会话状态。

## 4. 三维工作区（Cesium）

### 4.1 场景树与独立标绘

- 自由文件夹可以多级嵌套，里面可以混放 3D Tiles、GLB、GeoJSON、标绘 Graphic、影像等节点。文件夹不负责样式继承。
- 一次创建的单个 POI、线或面都是独立的 Graphic，有独立的样式。Ribbon 只提供**创建工具时的默认样式预设**，创建后样式会复制成对象自己的数据，不再追继承关系。
- 内部的 `GraphicLayer` 可以集中容纳很多 Graphic，不和场景树的某一项一一对应。要支持 500 个独立 POI 的搜索、多选、显示和批量属性处理。
- 场景树里的 GLB 和 Tileset 可以双击定位；3D Tiles 内部的 Feature 只能通过拾取查看，不能把它当成普通的、可以自由移动的三维独立对象。

### 4.2 标绘种类及交互

| 级别 | 类型 | 功能要求 |
|---|---|---|
| MUST | 普通点、图标点、文字、折线、多边形、矩形、圆或椭圆 | 创建对象、独立的属性和样式、编辑、保存后恢复 |
| SHOULD | 图文标牌、曲线、自由线 | 丰富的标注选项与控制点编辑 |
| SHOULD 或后期 | 直箭头、双箭头、攻击箭头、墙体、走廊 | 要有真实的几何和控制点逻辑；延期需记录原因 |
| LATER | 运动轨迹、动态时序对象、复杂雷达或军事标绘 | 不列入本轮的必达条件 |

- 连续放置 POI：点击 Ribbon 工具即进入该模式，预览跟随鼠标，单击直接创建并继续放置，不反复弹属性窗口；Esc 退出。
- 已有 POI 的“移动”用鼠标跟随定位，不用 Gizmo；默认在可见表面上拾取，必要时切换地形或椭球模式。预览阶段不改写正式存储。
- GLB 用局部或世界方向的 Gizmo 做平移、旋转、缩放；Tileset 只做整体的矩阵变换；一次操作完成后形成一条可撤销记录。
- 要区分贴地、绝对高程和拾取到的模型表面位置，不能简单地把地形贴地当成在 3D Tiles 任意表面贴合。`heightReference` 和地理坐标 Z 的含义要分清。
- 图标和文字可以属于同一个 Graphic，不必拆成两个树节点。Billboard 和 Label 要支持有实际意义的 Cesium 专业参数（anchor、offset、scaleByDistance、distanceDisplayCondition、disableDepthTestDistance 等），并清楚标注哪些是原生属性、哪些是软件扩展属性。

### 4.3 专业属性窗口

- 检查器：显示当前选择的常用参数，紧凑可编辑，可以固定；位置、经纬度和旋转只是其中一个折叠分类，不应占据主要篇幅。
- 完整属性：独立的非模态窗口，可以移动和调整尺寸，左侧是分类导航，右侧是专业表单，支持字段搜索、英文 API 别名、数值输入校验、默认值与单位，以及 Apply/OK/Cancel。
- 专项分类：3D Tiles（资源、可见性、样式、质量与 LOD、缓存、变换、裁剪压平、元数据与诊断）；GLB（显示、材质与动画〔适用时〕、变换、资源、属性）；Graphic（几何、图标与文字、距离条件、交互、业务属性）。
- 样式可以即时预览并取消还原；数值和 Gizmo 与表单不要求在同一瞬间双向实时联动，但**提交之后数据必须一致**。

### 4.4 3D Tiles 裁剪与压平

- 裁剪和压平是绑定到目标 Tileset 的**场景效果**，需要支持新建范围、编辑多边形顶点、参数窗口、实时预览、应用、撤销、启用停用、删除、项目持久化和重开恢复。不修改原始的瓦片文件。
- 裁剪优先使用 Cesium 原生的 `ClippingPolygonCollection`，需要时用 `ClippingPlaneCollection`，并明确保留内部还是外部的语义；要校验 WebGL 能力以及 Cesium 版本和 Tileset 的适配情况。
- 压平参考 `Nicander93/cesium-demo` 里局部 ENU 加 Canvas Mask 加 CustomShader 的实验思路，**禁止直接搬用写死高程、坐标系未对齐、没有纹理上限的代码**。目标高程必须可以设置，坐标空间要正确，并且要处理模型变换、多区域以及 Shader 之间的互斥与合成。
- 首轮验收至少用两套空间变换不同的真实 Tileset，在相机运动、LOD 切换、启用停用效果、保存恢复之后分别验证；测试不通过不得标记为已完成。

### 4.5 测量与空间分析

- MUST：三维空间距离、贴地距离、面积、高度差等基本测量；临时结果不自动写进项目。用户选择`保留测量`之后才生成独立管理的对象。
- SHOULD：基础的视线分析和剖面。视线分析要给出视线采样与可见结论，并说明精度边界；剖面要显示图表和采样点。可视域属于后续专项，不允许只画一个扇形就当成了真实的遮挡分析。
- 复杂工具使用**非模态的浮动参数与结果窗口**，地图视口不缩小；取消工具时恢复场景，应用之后可以撤销。

## 5. 数据资源与持久化

1. 统一的`添加数据`窗口：本地文件、本地目录、在线服务。二维和三维共用入口框架，各格式按需配置；支持拖拽添加，识别失败时才让用户选择格式。
2. 大型本地 3D Tiles 和 GLB 默认**引用**而不复制，项目里保存资源的 URL、绝对路径或相对路径。项目目录内的资源优先写相对路径；另存为时重新计算，不能把相对路径字符串原样复制过去。
3. 本轮不做自动的项目打包、外部文件批量复制和依赖收集 ZIP。现有的“场景资源包”若属于旧功能，可以保留兼容入口，但不能作为新工作流的主路径，也不是本轮的必达目标。
4. 本地源不存在时保留树节点和原有属性，提示`重新定位数据源`；允许重新定位父目录，批量修复同一来源下的多个资源。错误可以重试，但不删除项目里的对象。
5. `重新加载`只在用户明确触发时刷新外部文件；有未保存的矢量编辑时，应阻止静默覆盖，或要求用户明确选择。服务刷新不会把密钥写进项目日志。
6. **保存项目默认不覆盖外部数据源**，需要由明确的导出或写回操作执行；输入源不可写或格式不支持时，不提供写回选项。

## 6. 诊断与反馈

- `窗口 → 性能与诊断`：分为性能、资源、调试三个 Tab，默认关闭，支持浮动和停靠。
- 性能：FPS、帧耗时、能取到的内存信息。OpenLayers 静止时按需渲染，显示`空闲`，不要把 `0 FPS` 当成性能故障。
- 资源：Cesium 里已加载和可见的瓦片数、请求错误、层数、相机高度；OpenLayers 的图层、要素、瓦片请求、CRS、分辨率。指标在某些环境下取不到时，标注`不可用`或`估算`。
- 调试：适用时显示瓦片包围盒、LOD、加载错误、二维边界与网格等。资源开销大的诊断默认关闭，只在启用时采样，关闭后停止额外的性能工作。
- `窗口 → 任务日志` 独立于实时诊断，记录异步导入、处理、刷新和错误，支持取消、定位错误和重试。
