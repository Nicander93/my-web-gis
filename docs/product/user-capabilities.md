# 用户功能清单与改进顺序

本清单取代原来 S00–S10 的整包排期，改为按用户操作来跟踪能力。代码是否写完、浏览器里是否验证过、Windows 原生是否验收过，分开记录，不以“有接口”代替产品完成。

## 产品原则

- 地图和场景是主工作区；工具、表单和属性表只占必要的空间。
- 一个任务要有明确的入口和目标，浏览时的选择和编辑目标分开。查看不会自动打开大型面板。
- 表单以单行标签和紧凑控件为主；说明放进提示或帮助入口，不常驻占用空间。
- 常规的属性修改实时生效并且可以撤销；需要检查或准备的数据导入，保留明确的确认步骤。
- 少用重复的标题、分组解释和演示文案；分组要表达真实的任务关系。
- 选择、表格、定位和历史必须保持一致；失败、取消和关闭之后不能留下旧资源或只完成一半的结果。

## 已提供的工作流

| 工作流 | 当前能力 | 验证与边界 |
| --- | --- | --- |
| 创建与继续工作 | 创建二维地图或三维场景，打开和保存项目 | 两类工作区分别编辑；不提供项目类型的转换 |
| 二维数据组织 | 本地矢量导入，WMS、WMTS、WFS，图层排序、分组、显隐和属性 | 文件格式与服务配置以导入器支持的范围为准；WFS 是本地快照，不是 WFS-T |
| 二维要素操作 | 点击、框选、加选和减选，属性表联动，双击记录定位 | 浏览器里已有验证证据；图层的字段过滤和选择共同生效 |
| 二维样式与处理 | 样式、标注、过滤、空间处理及结果图层 | 草稿的应用和切换有独立流程；空间连接默认最多 100000 条，超限时整次失败 |
| 三维内容编辑 | 模型、Tileset、GeoJSON、影像、图形和水面；对象分组及显隐 | 仅限原生三维对象，二维的 vector 和 tile 不会自动显示在三维里 |
| 三维编辑与画质 | 移动、旋转、缩放，对象属性实时修改，场景质量设置 | GLB 的浏览器像素对比、历史和加载失败重试已有证据；硬件 GPU 和原生窗口不据此验收 |
| 场景交付 | 第 3 版场景 JSON、ZIP 资源包，旧场景迁移及内部运行时 | 保存内容不代表两个引擎渲染结果一致；引用的本地资源需满足打包约束 |
| 坐标系 | 4490、CGCS2000 3° 无带号 4534–4554、带号 4513–4533；二维视图切换 | 4490 和 4326 是椭球近似，没有格网改正；分带视图要求当前中心在对应的分带内 |

## 当前缺口与限制

- Desktop 已接通“地图可选择”，以及二维 Popup 的配置与显示，相关验证见选择策略和弹窗交付记录。Viewer 已有按配置显示 Popup 的路径，但显隐和过滤边界仍需单独验证。
- 表格键盘操作、二维历史、定位和地图取消已有浏览器验证，见键盘交付记录；Windows 上的实际输入法使用仍未验收。
- 嵌套分组、多视图和任意文档的完全无损往返都还未验收。Desktop 会规范化底图 ID，部分项目导入比共享文档的校验更严格。
- 旧 v3 中由三维影像迁移来的 tile 缺少来源标记，会按二维节点保留；只有从原始的 CityScene 重新导入，才能保留原生的 imagery 类型。
- 原生文件窗口、取消之后的本地缓存清理，以及真实硬件渲染，仍缺少原生验收。
- 数据源本身仍可能限制底图的清晰度；提高渲染分辨率并不会增加原始影像的细节。

## 不承诺的内容

同一份文档在二维和三维两个引擎中渲染出相同结果、二三维交互对等、三维 WMS 与鉴权瓦片和复杂分级符号、公共包的 npm 发布，以及北京 54 和西安 80 的格网改正，都不在当前排期内。内部包保持清晰的边界，不会扩张成一个新的 SDK 发布项目。

## 下一批小 PR

| 顺序 | 用户得到什么 | 验收条件 |
| --- | --- | --- |
| 1 | 图层可以限制地图上的浏览选择 | 关闭后点击和框选都不改变选择；表格仍然可以查看、选中记录和定位；默认保持原有行为；实时生效并且可以撤销 |
| 2 | Popup 的配置和查看入口更明确 | 紧凑的设置；字段和标题生效；属性文本安全显示；没有配置、已关闭或被过滤掉的要素不会误弹；不把浏览变成编辑 |
| 3 | 表格键盘操作稳定 | 输入框里的 Delete、Backspace、Ctrl+Z 不会删除要素或触发项目撤销；行上按 Enter 定位；Escape 取消当前的地图手势 |
| 4 | 国内投影形成完整闭环 | 补齐 4513–4533；地图视图的投影切换、选择和导出保持一致；明确近似精度 |
| 5 | 继续验证剩余交互 | 每次选一条工作流补充证据，发现产品缺口就单独修复 |

产品的取舍和验收由当前任务负责。每个小 PR 完成实现、范围匹配的测试和记录后，审查合入；不等待另一个产品角色，也不一次把所有可选项都铺开。
