# Desktop WebGIS Agent 分阶段实施与验收计划

> 版本：Implementation Baseline 1.0 · 2026-10-13  
> 主仓库：<https://github.com/Nicander93/my-web-gis>  
> 参考仓库：<https://github.com/Nicander93/cesium-demo>  
> 静态对照版本：`my-web-gis` main `015774120577546514baadd30cc22b1c79d9dbe4`；`cesium-demo` main `418dd9a9735bb43e8c1402e71e26c34d8fb8a15d`。实施开始时**先 fetch 最新 main**，不要将此 SHA 当作永远最新。  
> **目标：真正可运行的二维 + 三维桌面 GIS 产品化重构**，不是一版静态 UI。

## 0. Agent 先做这些（不可跳过）

1. 读取交付包 `README.md`、`AGENT_TASK.md`、`docs/01...04...` 和两个 HTML；用 HTML 理解 UI，使用规范补足业务与安全要求。不得照搬 HTML 的模拟业务数据或模拟结果。
2. Clone/pull **最新代码**，记录 `git rev-parse HEAD`；新建独立分支如 `feat/desktop-workspace-productization-v1`。**不得直接向 main/master 推送**；最终提 PR。
3. 检查当前仓库 `package.json`、现有 packages、所有测试与 Tauri 构建脚本；运行初始 `pnpm install --frozen-lockfile`、`pnpm build`、`pnpm test`、`pnpm --filter @desktop-webgis/desktop test:e2e`（受运行环境限制的项目需单独报告，不能隐瞒）。
4. 盘点当前功能，将需求标记 `现有可用 / 现有但需修复 / 新增 / 延期`；列出潜在迁移与数据损失风险。**保留代码中已有能力**，勿因为重做页面而让字段过滤、服务图层、导出等消失。
5. 先修复关键契约与 Shell，再批次迁移功能；每阶段 build/test/截图、独立提交，防止一次性巨型 diff 失控。
6. 不存在可靠数据或算法时，不得伪造：不得仅接展示按钮、使用硬编码结果或生成 PNG 冒充动态运算。

## 1. 本轮优先级及完工定义

| 层级 | 本轮含义 | 范围 |
|---|---|---|
| P0 / 必须 | 没有则不算本轮完成 | Shell/Docking、2D 原有核心功能可用、3D 基础图层/独立 Graphic、专业属性窗口、项目与资源安全、基础裁剪、基础局部压平、基础测量、诊断入口、E2E |
| P1 / 优先 | 在 P0 稳定后继续，同一轮应尽可能闭环 | 矢量复杂拓扑编辑、POI 图文标牌与高级样式、基础通视/剖面、批量对象编辑与表格增强 |
| P2 / 暂缓 | 不影响 P0 验收 | 高级可视域/淹没/开挖方量、动态路径与军事箭头全集、二三维联动、项目资源打包 |

**压平标记规则：** 本轮 P0 不是只实现“压平”按钮。若 GPU/模型兼容性验证失败，应明确标记 **P0 blocker：压平未达标**，提供重现数据、日志和原因，不能将其无提示降级为灰色占位或伪实现。可以并行推进其他模块，最终交付需要用户接受该例外才能关闭。

## 2. 里程碑和依赖

```text

 ├───────────┬───────────────┐
 ↓           ↓               ↓
M2 2D        M3 3D Scene     M6 项目与数据资源

M4 2D属性表   M5 3D标绘       M7 项目恢复与重定位
```

可并行处理 UI 层与算法包，**但不能**让两个 Agent 并发重写同一 `project.store.ts`、场景 Schema 或 Docking Host。公共接口先冻结再并行。

## 3. M0：基线与契约审计

**任务**：

- 记录最新代码 commit、依赖和构建结果；列出现有功能、阻塞测试及真实可用数据集。
- 为旧 `.webgis.json`、`CityScene v1/v2`、`SceneDocument v3` 准备最小兼容 fixtures；保存→打开→数据等价检查。
- 对二维/三维分别采集工作区初始截图；记录错误、不完整功能和必须保留的原有入口。
- 明确代码里 `apps/desktop/src/features/city`、`packages/cesium-layer`、`packages/cesium-scene-runtime`、`packages/scene-schema` 的依赖边界。

**验收**：有测试基线报告和依赖图；旧项目 fixture 能读；现状问题与后续改动能追踪。

## 4. M1：桌面外壳和 Docking

**任务**：

- 统一 `App Shell`：应用菜单、Ribbon Tabs、Ribbon Tools、状态栏，严格三行顶部。
- 实现 `DockingHost`/`WindowRegistry`：左/右/底、浮动/停靠、拖拽、缩放、关闭、恢复、焦点/Z-index、布局保存/重置、跨屏幕边界修正；原型外观一致。
- 地图/Cesium Canvas 绝对铺满整个 Workspace；面板使用 overlay；底部属性表横跨 Workspace。
- 移除固定 `restore-trigger` 悬浮边缘条；`窗口`菜单统一控制面板。
- 集成通用工具会话协调和 Esc/快捷键焦点保护，2D 和 3D 共用接口但不共用渲染工具。

**触及代码**：`app/{App,Header,Workspace,LeftPanel,RightPanel,BottomPanel}.tsx`、`stores/workspace.store.ts`、3D `CityWorkspace`、相关 CSS 和公共组件。

**验收**：2D、3D 在 1366×768 和 1920×1080 下窗口可拖动、关闭/恢复、保存布局；地图真实 Canvas rect 不随面板切换改变；双击定位在完整视口中央；焦点和 Esc 无冲突。

## 5. M2：二维图层与编辑工作流

**任务**：

- 将二维 `Workspace` 迁移到新 Shell；保留地图绘制、选择、图层树、已实现的编辑与导出。
- 文件夹任意深度嵌套、拖拽排序、显隐/锁定继承、右键菜单；迁移旧单级 Group，不丢弃图层顺序。
- 完善二维几何编辑：点/线/面绘制、顶点、删除、移动、撤销/重做；能力不存在时给明确 UI 原因。
- 区分`赋予 CRS`和`重投影数据`两种不同操作；保证正确的源/显示 CRS 与输出。

**触及代码**：`features/map`、`features/layers`、`app/commands/{map,edit,layer}.commands.ts`、`packages/{gis-core,ol-runtime,ol-scene-runtime,ol-selection,vector-io}`。

**验收**：二维真实 GeoJSON 导入、选中、编辑、Undo/Redo、保存重开、导出；新/旧文件夹层级不串行或丢 ID；坐标正确；无页面仅模拟要素。

## 6. M3：三维场景与属性编辑

**任务**：

- 保留独立 3D 项目，渐进替换 `City*` UI 命名；公共 Schema 继续能读取旧版。
- 实现自由嵌套文件夹、独立对象 ID、地图/树联动、双击定位、右键专业属性、Tile Feature 与 Tileset 分离。
- 完整属性窗：Tileset、GLB、Graphic、GeoJSON、文件夹的类型专用表单；字段搜索与英文 API 别名；支持 Apply/OK/Cancel；检查器可固定对象。
- 复用 `cesium-tileset-edit` Gizmo 的移动/旋转/缩放（GLB 与 Tileset 整体），维护正确撤销粒度。

**验收**：打开真实 Tileset/GLB、切换文件夹/选择、修改专业参数、保存重开；属性窗目标 ID 不因场景选择变化而跳变；Tile 子对象元数据仅在拾取面板显示。

## 7. M4：二维属性表与空间处理

**任务**：

- 属性表重组为一个 Docking 视图（多图层 Tab），保留现有搜索、筛选、统计、单元格编辑、排序等实现。
- 补齐字段管理、过滤已选、字段计算器：**表内计算为原数据修改**、**处理工具箱计算为新输出**，原子操作、类型校验、无半成品。
- 实现或完善面合并/分割、缓冲区、叠加裁剪/差集/交集等真实算法（利用现有 `packages/spatial-analysis`，不要 UI 重写算法）。
- 多选状态、地图/表联动与定位动作一致；任务工具能中止、报告进度、输出新图层。

**验收**：至少执行 3 组多要素编辑和 4 组空间运算，以已知输入/预期 GeoJSON 拓扑断言；字段计算报错后输入数据不变；属性表行选中不自动定位。

## 8. M5：三维独立 Graphic 与标绘

**任务**：

- 在 `cesium-scene-runtime` 内维护共享 `GraphicLayer`（或少数按能力分组的 Render Pools），替换每个 Graphic 独立 DataSource；稳定 ID、增量更新、选择高亮、正确清理。
- 扩展 `GraphicGeometry` / `GraphicStyle` / 验证器；实现点、Billboard、Label、线、面、矩形、圆/椭圆及独立样式；POI 图片/Label 组合。
- 连续 POI，Esc 退出；已有 POI 鼠标跟随移动；线/面 Enter/右键完成、Backspace 回退；不弹出重复属性窗。
- 批量对象操作、复制粘贴、撤销/重做；图标/文字距离显示和拾取模式。

**验收**：生成 500 个独立 Graphic；树可以搜索/多选/显隐，批量编辑不修改非目标字段；渲染层个数不会线性随 POI 数增长；重开项目 ID、样式、位置全部保持；工具切换后无遗留 handler/Entity。

## 9. M6：统一数据导入与资源引用

**任务**：

- `添加数据`统一窗口（本地文件 / 本地目录 / 在线 URL），按 2D/3D 能力选择配置页；拖入文件、资源验证和错误处理。
- 2D 保留 GeoJSON、SHP ZIP、DXF、CSV、WMS/WMTS/WFS；3D 支持本地 `tileset.json` 目录及 HTTP(S) Tileset、GLB、GeoJSON。
- 资源定位采用项目目录基准的相对路径和外部绝对路径；Tauri 资源协议需保证 Tile/GLB 引用、相对纹理路径、资源访问安全、MIME 和必要的 Range 行为。
- 源文件/场景项目保存互不覆盖；加载失效后保留节点状态并可`重新定位`、`重试`、`重新加载`。

**验收**：从 D 盘引用模型、项目另存到 E 盘，引用仍有效；工程整体移动且保持目录内相对资源时可重开；换一份无效路径后重定位恢复；缺失数据不影响其他层保存；不存在对外部文件隐式覆盖。

## 10. M7：安全保存与恢复草稿

**任务**：

- 保存、另存为安全写入，失败保持旧文件、dirty 和恢复草稿；不同项目持久化布局互不串行。
- Crash Recovery：周期性恢复快照、启动比较、恢复/舍弃、缓存清理、格式版本/容量保护。
- 窗口布局单独保存，**不把 Dock Geometry 写入项目**；凭据仅本机安全存储/会话缓存。

**验收**：模拟写入失败、进程异常退出、打开损坏项目、切换项目、保存期间变更项目，正式项目内容不损坏；恢复后对象与图层编辑一致。

## 11. M8：3D Tiles 裁剪、压平与基础测量

**任务**：

- 新增 `packages/cesium-tileset-effects` 或经过论证的等价独立包；将裁剪、压平效果作为 Tileset 子配置持久化。
- 裁剪：基于 Cesium 原生 ClippingPolygon/Plane，支持多范围、内部/外部、控制点编辑、启停、删除、预览、撤销。
- 压平：结合 `cesium-demo` 的 shader-mask 思路先完成坐标系统一、动态目标高度、Canvas 尺寸上限、效果组合、资源生命周期，再接 UI；不得直接拷原型固定 405 m。
- 基础三维测量：空间距离、贴地距离、面积、高度差；临时与持久结果严格区分。

**验收必须提供：**

1. 两套**变换不同**的实际 Tileset 测试数据，说明坐标框架、Cesium/WebGL 版本、是否存在自定义 Shader。
2. 裁剪：内部/外部、两个不重叠区域、取消/恢复、Reload/Save 重新打开、选中目标不影响其他 Tileset。
3. 压平：不同目标高程、变更控制点、已有平移/旋转、相机运动、LOD 切换、关闭效果恢复模型、GPU 资源清理。
4. 非支持场景必须得到明确诊断，不可假装成功。模型本身缺少足够几何细分时如有边缘瑕疵，应记载限制和可复现步骤。
5. 每个已应用操作具备 Undo/Redo 和保存恢复；按 Esc 撤销草稿后场景未被修改。

## 12. M9：诊断、UI E2E 与整体验收

**任务**：

- `性能与诊断`通用 Docking Window：性能、资源、调试三 Tab；按当前引擎采集真实可用指标，帧率按需渲染显示空闲。
- 任务日志窗口记录资源请求、算法、文件 IO、任务耗时/错误原因与重试；诊断窗口不冒充日志。
- 统一状态栏、帮助、快捷键说明、菜单权限；最后完成 UI 密度与视觉复核。
- 增加 Playwright 测试覆盖窗口/模式、项目类型、资源故障、POI、属性表和属性窗；3D GPU 渲染测试需专门环境验证，必要时增加手动验收矩阵。

**验收**：软件真实启动；2D/3D 功能各完成端到端闭环；没有前端异常/泄漏导致频繁卡顿；性能指标不硬编码。

## 14. 每阶段提交与汇报格式

Agent 每个阶段输出（可以用 Markdown）：

```text
阶段：M# / 标题
完成的真实功能：...
保留/修改/新增的文件：...
业务或 Schema 迁移：...
执行的命令与结果：...
截图 / 测试数据：...
未完成 / 阻塞项：...
下一步与风险：...
```

不得使用“已优化界面”“已实现功能”这种无法核验的汇报；必须指向代码、可操作路径、真实输出和可重复测试。

## 15. 最终 PR Gate（均须满足或列为用户接受的例外）

- [ ] main 最新基线与最终分支差异说明、每阶段独立提交。
- [ ] `pnpm build` 成功；`pnpm test` 成功，或明确列出原有失败与此次引入的失败。
- [ ] Desktop E2E 在可用环境运行；未运行项准确标记。
- [ ] 2D 与 3D 的真实功能均具备核心闭环，不是复刻 HTML 的假应用。
- [ ] 20 条 E2E 验收矩阵逐条出结果和证据；对未支持的 GPU 环境记录复现方式。
- [ ] 旧项目、旧 CityScene 和 SceneDocument 兼容测试通过。
- [ ] 复杂工具操作有取消/回滚/持久化/资源清理/错误反馈。
- [ ] Docking 默认状态、全屏画布、完整中心定位符合 HTML 基准。
- [ ] 原仓库已有的二维服务、导入、导出、分析不出现不解释的功能倒退。
- [ ] README 更新使用与开发方法、快捷键、算法限制和已知问题。
- [ ] 提供最终 PR 链接、构建/测试日志、2D/3D 截图及阻塞记录。

**停止条件**：如果涉及核心项目文件格式破坏、无法保全旧项目或可能写坏用户数据，先停止该改动并给出兼容迁移/回滚方案，不得绕过验证强推。
