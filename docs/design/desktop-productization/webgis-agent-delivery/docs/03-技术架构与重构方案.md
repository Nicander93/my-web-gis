# Desktop WebGIS 技术架构与重构方案

> 版本：Implementation Baseline 1.0 · 2026-10-13  
> 代码依据：`Nicander93/my-web-gis` 当前默认分支的静态阅读；`Nicander93/cesium-demo` 算法原型静态阅读  
> 注意：**尚未在本交付轮次运行仓库构建、测试和真实 Tileset 渲染**。代码现状评估不是功能验收。

## 1. 技术目标与禁止项

目标是对现有 **React 19 + TypeScript + Vite + Tauri 2 + OpenLayers 10 + Cesium** monorepo 做整体 UI 产品化重构，同时保留已有可复用 GIS 能力。

**架构要求：**

1. **桌面 Shell 统一**，二维/三维 Workspace 独立；不做处处 `if (is3d)` 的万能组件。
2. App 负责 Project、业务命令、文件 IO、窗口管理；GIS 包负责算法、渲染和独立 API；领域 Schema 不依赖 React/DOM。
3. 继续保留独立可发布的 `@desktop-webgis/cesium-layer`、`ol-*`、`vector-io`、`spatial-analysis` 等包；避免把业务强耦合塞进底层包。
4. 优先保留旧项目兼容、数据安全、编辑撤销机制，**禁止为了 UI 改造删掉旧业务能力或数据**。
5. 真实 GIS 结果可证明。不得用 `toast('已完成')`、静态 SVG、虚构指标代替运算结果。PR 必须有截图、测试和能力清单。

## 5. Scene / Folder / Graphic 模型

当前 `CityScene` 是旧序列化结构，具有 `groups?: CityGroup[]` 与每个节点 `groupId?: string`。改为多级文件夹前必须定义结构迁移：

```ts
// 目标概念示例（非强制字段/最终 Schema）
type SceneObjectId = string;
interface FolderNode {
  id: SceneObjectId;
  kind: 'folder';
  name: string;
  parentId?: SceneObjectId;
  visible: boolean;
  locked: boolean;
}
interface GraphicNode {
  id: SceneObjectId;
  kind: 'graphic';
  parentId?: SceneObjectId;
  visible: boolean;
  locked: boolean;
  geometry: GraphicGeometry;
  style: GraphicStyle;
  properties: Record<string, JsonValue>;
}
interface TilesetEffect {
  id: string;
  kind: 'clip-polygon' | 'clip-plane' | 'flatten';
  enabled: boolean;
  geometry: unknown;    // Schema 中细化为类型化/可验证几何
  options: unknown;     // Schema 中细化为经过版本校验的选项
}
```

约束：所有节点 `id` 唯一；父子关系不得成环；移动节点/删除文件夹对后代应用明确语义；旧单级 Group 迁移到 `parentId`；可见/锁定为组合有效状态而非覆盖子项；渲染顺序受控制。**Graphic 是用户对象不是 GraphicLayer**。

### 5.1 共享渲染池设计

当前 `CitySceneRuntime.createLayer()` 在 `graphic` 情况构造 `new GraphicLayer({ ...base, graphics:[node] })`。目标改成内部一个或少量 GraphicLayer 实例，按用途/渲染能力分桶，同时保留：

- `graphicId → Graphic instance`、`graphicId → rendering collection`、`picked Entity → graphicId` 快速映射。
- 一次性增量 diff：新增、删除、只改图标/样式、显隐、位置、文件夹归属变更；不要任意 UI 更新就销毁全部 DataSource。
- 选择集单独存储；高亮是临时效果，不写入原始样式，也不全量重建 500 个 Entity。
- 用户保存只序列化 `GraphicNode[]` 及树结构，不把底层图元或临时 DrawSession 保存进文件。
- 不改现有 `GraphicLayer` 对开发者的 `addGraphic/getGraphic/removeGraphic/startEditing` 等外部 API；内部支持批量更新、资源复用、正确 dispose。

### 5.2 Graphic 类型与样式扩展

`GraphicGeometry` 建为 **discriminated union**：`point | polyline | polygon | rectangle | ellipse | curve ...`；保留未知扩展的兼容策略、输入校验与迁移。

`GraphicStyle` 根据 `Graphic` 可视组件拆分：`billboard`、`point`、`label`、`polyline`、`polygon`、`distance`/`visibility` 等显式可选子结构，允许图标与标签同时存在。默认预设通过绘制工具工厂**在创建时复制**，不是图层级继承，不要求一个 `GraphicLayer` 对应一个节点。

不要盲目复制 Cesium 对象（Color、Cartesian3、CallbackProperty）到 Project；项目 JSON 只能存规范化可验证的纯数据。

## 6. 统一编辑模式与命令

建议 `OperationController` 管理全局**单一活动地图交互操作**：

```ts
interface ToolSession {
  id: string;
  kind: string;
  cancel(): void;
  finish?(): Promise<void> | void;
  dispose(): void;
}
```

- 每个 Workspace 同一时刻只允许一个占用地图输入的工具；新工具激活应正确取消/提交上一工具。
- 工具返回**业务数据结果**而不是直接写 Project；成功由 `ProjectCommand` 生成一次可撤销修改、标记 dirty、触发 Runtime 增量更新。
- 临时绘制内容、控制柄和拾取提示不进入保存快照。Esc 退出当前模式并清理资源；文本/属性表焦点先消化键盘事件。
- 3D Gizmo 复用 `cesium-tileset-edit`，POI 用鼠标跟随放置/移动，二维矢量编辑保留 OL 工具体系。
- 历史命令粒度：一个标绘成功创建 = 一条；一段 Gizmo 手势 = 一条；批量修改 = 一条；多步复杂处理结果创建 = 一条原子命令。

## 7. 3D Tiles Effect Engine

建议新包 `packages/cesium-tileset-effects`，依赖 Cesium peer dependency；无 React/UI、无 App Store：

```ts
interface TilesetEffectManager {
  setEffects(tilesetId: string, effects: readonly TilesetEffect[]): void;
  removeEffects(tilesetId: string): void;
  destroy(): void;
}
```

### 7.1 多边形裁剪

- 利用 Cesium 对指定 Tileset 的 `ClippingPolygonCollection`；适用平面裁剪时用 `ClippingPlaneCollection`。
- 记录 `keepInside/keepOutside` 与 Cesium `inverse` 的实际对应关系，**以真实渲染测试判定方向**；支持功能检测（WebGL/tileset capability）、效果开关、顶点重编辑与撤销。
- 目标 Tileset 独立持有其 effect set；不修改其他模型或地形。多个裁剪区域的组合语义必须提前明确，并测试重叠、相离、多边形方向、数值稳定性。

### 7.2 局部压平

参照 `Nicander93/cesium-demo/src/views/tile-local-flatten/useTileLocalFlat.ts`：

- 原型将绘制点映射到以 Tileset 中心生成的 ENU 坐标和 Canvas Mask，`CustomShader.vertexMain` 根据采样结果改写顶点高度。
- **原型缺陷**：固定 `vsOutput.positionMC.z=405.`；`vsOutput.positionMC.xy` 未必与外部构建的 ENU Mask 坐标一致；Canvas 尺寸简单按米数乘系数，无显式 GPU 纹理上限；Canvas 被 append 到 body；多 Shader 共存、释放和跨 tileset 支持不足。
- 必须显式构建 `model→world→ENU` 或 `world→ENU` 变换，验证 `positionMC` 的实际空间；高度应从目标椭球高程/本地平面高程正确映射回模型坐标，不是无条件赋值 Z。
- Shader/Mask 资源复用，必要时聚合多个效果；预览与正式配置隔离；销毁时删除监听、纹理与 shader。避免一个效果覆盖已有 `customShader`（如材质/色彩风格）。
- 多 LOD、非平移模型变换、倾斜表面、细分不足导致边界接缝均要验证；未满足精度条件时告知限制，不能声称精确地形重建。**先做算法验证，再做完整 UI 按钮**。

`cesium-demo` 的 `mask1/texture-mask.ts` 等主要用于**像素后处理遮罩/表现**，不是可以自动替代 3D Tiles 原生几何裁剪的技术方案。

## 8. 数据 IO、外部路径和项目安全

### 8.1 资源模型

使用带协议类型的资源引用，而不是未经验证的字符串拼接：

```ts
type ResourceRef =
  | { kind: 'relative'; path: string }
  | { kind: 'absolute'; path: string }
  | { kind: 'url'; url: string; credentialRef?: string };
```

序列化时可兼容旧字符串字段；解析时统一在资源解析器转换。相对路径以**项目文件目录**为基准（而非浏览器 `document.baseURI`），另存为需重新计算。禁止跨越未经授予的本地文件根、随意 `file://` 直读任意位置；Tauri/浏览器差异由宿主能力适配器处理。

针对 3D Tiles 目录：本地 `tileset.json` 的子 tile、glTF、纹理与 nested tileset 需要一个一致的 URL/base path 解析器；根据 Tauri 安全/asset protocol 的限制必要时实现受控本地资源服务器或协议处理，支持 `Range`/MIME/大量小文件；禁止只把根 JSON 转成 Blob 而导致相对依赖全部失效。

### 8.2 项目保存和恢复

- 当前项目主路径是 `.webgis.json`，旧版 `ProjectSnapshot` 里可能直接包含矢量 Feature 数据。保持已导入旧项目可读，按新资源模式渐进兼容。
- 安全写：先写同目录临时文件、校验/同步后替换正式文件（平台能力允许时），失败保留原文件与 dirty。
- 恢复草稿为本机缓存，包含项目 ID/路径、基准文件修改时间、快照版本、修改时间、内容/恢复元数据；遇到版本冲突需显式提示。
- 丢失资源保留对象和原有样式变换/树位置，标记 error；重新定位资源后增量重载。修改原矢量数据源必须独立显式命令，保存项目不写回源文件。
- 本轮不做完整项目包导出；当前仓库已有 `exportSceneArchive` 等旧功能可保留兼容，但不自动纳入新创建/保存主线，删除前必须有迁移与测试证据。

## 9. UI 层实现建议

- 统一基础控件：菜单、Popup、Tabs、NumericInput、Form、Tooltip、Dialog。可优先评估 Ant Design 作为**通用控件基座**，不要为了它改写 GIS Runtime；按原型覆盖样式 token。
- Docking Panel `PanelRegistry`：注册 `id/title/allowedDock/defaultSize/renderer`，负责打开/关闭、停靠/浮动、尺寸、焦点、存储、屏幕适配。
- `LayerTree`/`SceneTree` 共用可视化树行为，采用不同 `TreeAdapter` 将 2D layer 与 3D scene item 映射到 `TreeItem`。避免把所有真实 GIS 能力揉入通用 TreeItem。
- 属性编辑器按类型注册编辑页面（schema/editor registry），不以巨大的 `if(node.type)` 单文件堆积数千行；字段验证与序列化归领域层。
- 工具命令提供 `isEnabled(context): {allowed,reason}`；Ribbon 和右键菜单共享同一能力判断源。
- `DiagnosticsProvider` 定义公共采样协议，二维/三维分别适配；不可用指标返回有意义的 unavailable 标志，而不是 0。

## 10. 迁移与测试策略

**必须先建立回归基线，再重构：**

1. 记录当前构建/test/E2E 情况；保留并修复现有单测，不可一律跳过。
2. 新增旧版 `.webgis.json`、`CityScene v1/v2`、公共 `SceneDocument v3` fixtures；在迁移后执行读/写/再读校验。
3. Docking 替换时保持 2D / 3D 地图 mount/unmount、ResizeObserver、Cesium viewer 的资源释放；面板显示/隐藏不重新创建 Viewer。
4. 所有 package `pnpm -r build`、`pnpm -r test`（以实际仓库脚本为准）及桌面 UI E2E；测试报告列出未运行项而非“通过”。
5. 3D 真实数据测试必须使用可独立访问的测试 Tileset，而不仅是截图；测试包含至少两套不同坐标/变换、不同 LOD、资源重载、Shader 清理与相机移动。
6. 性能基线：普通 500 POI 的选中/搜索/显隐需无明显冻结；较大数据集要测虚拟树与对象 diff；可记录硬件、Cesium/WebGL 能力、指标采样方式，不凭空承诺帧率数字。

## 11. 不建议的重构方式

- 一次将 `City*` 全部机械改名为 `Scene*`，却没有迁移器、回归验证或引用审计。
- 将 3D Tiles 与 GLB、POI、矢量 Feature 强制统一为一套可编辑几何数据模型。
- 为每一个 Graphic 建独立 Cesium `CustomDataSource`，或用户拖文件夹就整体重建所有 Entity。
- 将裁剪、压平 Shader 放进 `CityWorkspace.tsx`；或把示例 `drawUtil.clear()` 直接用于真实 Viewer（会清除不属于它的 Entity）。
- 提交“功能演示成功”的纯 UI 无算法实现；或注释掉失败测试后宣称验收通过。
