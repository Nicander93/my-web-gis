## 1. 用户的产品设计理念

用户关注的是长时间实际使用的桌面 GIS 工具。设计要让人迅速找到对象、执行操作、观察结果，并尽量保留地图、模型和数据表的空间。

| 原则 | 从用户反馈提炼的要求 | 具体设计约束 |
| --- | --- | --- |
| 工作内容优先 | 地图、模型、数据应占据主要空间 | 已可工作的画布不放介绍区；常驻区域必须承载操作、对象或状态 |
| 默认紧凑 | 属性表单、下拉框和标题太占空间 | 简单属性使用同一行的标签和值；去掉重复标题和独占一行的统计信息 |
| 帮助按需出现 | 参数说明适合放在 info 或悬停提示中 | 不常用的解释按需显示；明显的动作不再加说明；不要给每个字段机械添加 info 图标 |
| 减少重复表达 | 欢迎页、Ribbon、面板重复介绍自身 | 一个区域只表达一次身份；分类标签不再重复解释按钮；重复入口只在提高操作效率时保留 |
| 操作直接生效 | 修改属性后不应再次点击应用 | 普通属性有效修改即时反馈，支持撤销；保存项目仍是独立动作 |
| 层次来自结构 | 现有界面缺少产品层次 | 用对齐、分组、选中状态、少量字重和边界表达层次，减少装饰性标题与分隔条 |
| 专业工具的完整性 | 手柄跟随、箭头、清晰度、场景设置都影响体验 | 控件正确跟随对象；提供合理画质默认值及可调参数；状态和错误要准确 |
| 操作对象明确 | 浏览、编辑、查看属性和查看表格不应互相误切 | 图层／对象的绑定独立；在操作位置说明目标和范围，不用介绍文案替代真实状态 |
| 持续工作可恢复 | 收起、切换、取消与失败后仍能继续 | 区分已保存、已提交与草稿；保留必要输入，失败就近可恢复，键盘和 DPI 一起验收 |
| 从真实任务验收 | 功能可用仍可能像 demo | 验收包含首次进入、持续编辑、窗口缩小、错误恢复、保存重开，而不只看按钮存在 |

这里的“少文字”主要指去掉无助于当前操作的文字。命令名称、字段名称、单位、当前编辑目标、过滤范围、错误原因仍然有价值。欢迎页的空侧栏应删除；工作区的图层／对象树有实际职责，应保留并允许收起。

这些原则比更换字体、增加动效或调整品牌色更优先。现有项目规范也已经提出地图优先和专业信息密度，但最近补丁增加了与这些目标冲突的引导和标题层级。

“紧凑”需要同时满足少层级、短路径、可扫读和可靠反馈。只把 40px 控件缩成 24px，或者把所有按钮改成图标，不能解决重复身份、提交规则不一致和目标不清的问题。常态保持轻量；发生错误、执行复杂事务或需要作关键决策时，允许增加必要信息。

## 2. 成熟产品值得借鉴的设计思路

下面区分公开资料描述的产品行为与本项目的设计判断，避免把某个产品的界面照搬为标准。

### QGIS：对象、工具与真实状态围绕数据组织

QGIS 属性表支持停靠和独立窗口，集中提供编辑、选择、过滤等工具，并显示总数、过滤数、选中数。它保留了专业数据操作所需的状态。[QGIS 属性表官方文档](https://docs.qgis.org/3.44/en/docs/user_manual/working_with_vector/attribute_table.html)

本项目借鉴其对象上下文和数据状态；针对只有一个停靠表的当前结构，把统计移到分页底栏，把图层选择与工具放在同一行。不照搬 QGIS 的独立窗口标题或全部工具按钮。

QGIS 的处理工具箱另有工具搜索、参数与运行日志、帮助入口，便于查找工具和追踪执行。[QGIS 处理工具箱官方文档](https://docs.qgis.org/3.44/en/docs/user_manual/processing/toolbox.html)

本项目可借鉴任务参数、结果与帮助的分工。现有 18 个工具先解决重复标题和说明，不为模仿大型工具箱提前增加多列界面；工具搜索、最近使用和执行历史按实际使用频率逐步引入。

### VS Code：主工作区稳定，辅助区域可以收起和恢复

VS Code 支持调整面板位置、切换侧栏和面板显示，以及隐藏辅助界面的 Zen Mode；窗口标题也可以反映当前工作上下文。[VS Code 布局官方文档](https://code.visualstudio.com/docs/configure/custom-layout)

本项目借鉴“需要时打开、关闭后能恢复”的面板行为。面板关闭不应丢失目标、大小、输入和滚动位置。窗口宽度不足时先处理低频命令和辅助区域，保持当前任务可继续。

### Windows 桌面工具栏：效率与清晰度需要同时考虑

Microsoft 的传统桌面工具栏指南区分菜单的完整性与工具栏的高频操作，并强调节省工作区、保持命令可识别。该指南是 Windows 7 时期资料，本项目只采用其仍适用的交互原则，不采用其视觉样式。[Microsoft 桌面工具栏指南](https://learn.microsoft.com/en-us/windows/win32/uxguide/cmd-toolbars)

本项目保留不够直观的命令文字，例如“定位图层”“空间处理”；移除“导航”“导入”“查看”这类再次描述按钮所属分类的文字。常见图标按钮提供名称和快捷键提示，不能要求用户逐个悬停才能找到常用命令。

### 渐进呈现：把辅助解释放到需要它的时刻

NN/g 的渐进呈现原则主张先提供常用能力，把低频或复杂选项放在容易发现的次级入口。[NN/g 渐进呈现](https://www.nngroup.com/articles/progressive-disclosure/)

Microsoft 的 tooltip 指南将提示定位为补充信息：关键任务信息应直接可见；提示也不适合承载必须注意的错误、警告或长篇交互内容。[Microsoft 提示设计指南](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/tooltips)

因此，“使用说明”可以进入帮助，“参数为什么这样设置”可以进入 info；坐标系缺失、导入失败、当前修改尚未保存等内容必须在对应位置直接显示。info 支持悬停和键盘焦点；需要阅读较长内容时提供可点击的说明面板。

### My3dtiles：借鉴属性密度和操作反馈

用户提供的截图呈现了连续的对象树、按组组织的属性、三轴手柄、场景分辨率及渲染参数。这些适合作为本项目专业属性编辑的参考。

本次仅根据提供的截图总结，没有重新操作 My3dtiles。截图也展示了较长的技术属性列表和较宽的侧栏；本项目需要按使用频率取舍字段，不能以原始 API 字段数量判断产品成熟度。

### 3.1 全量审计补充的主要问题

这些问题此前的六批计划没有覆盖，细节和证据见[跨界面台账 F01–F24](product-interface-audit-2026-10-08.md#3-跨界面问题台账)：

- **属性生效规则不完整**：GLB 地理位置、水面材质、标绘样式和分组名称仍需额外应用；二维样式／标注有草稿但缺少统一实时预览契约。
- **数据与处理页面仍有教程布局**：服务目录常驻实现说明；CSV 有嵌套 overlay；18 个处理工具共享的参数区有多层重复标题，几何报告空间开销大。
- **目标、范围与词汇不一致**：要素空态没有充分区分多选和跨图层；统计范围不同于表内搜索结果；部分英文／内部符号、CSV 坐标名称与复制模式文案不准确。
- **持续工作与恢复欠统一**：局部草稿的关闭／切换规则不同；主菜单与 resize 缺少一致键盘行为；错误可能被下一条普通状态覆盖。“关于”当前只是日志输出。
- **原生与浏览器边界欠验证**：二维矢量导出与项目／三维导出的宿主适配不同；原生未保存关窗需要专门验证，现有 beforeunload 不能作原生保证。
- **Viewer 被漏出设计范围**：大浮卡和常开面板覆盖地图，分类图例只取首项，三维对象列表未表达完整分组显隐；窄屏、局部加载失败和恢复需要独立完善。

已经较好的行为也列入保留范围：独立编辑目标、明确表格／检查器绑定、共享上下文菜单、面板尺寸与专注模式恢复、样式草稿保护、三维实时变换／场景设置、渲染偏好与项目分离、WFS 刷新失败保留旧快照。审计不要求把这些能力推翻重做。

## 4. 全产品的目标设计

### 4.1 起始页：只负责开始和恢复工作

无项目时直接提供同一层级的三个入口：`新建二维地图`、`新建三维场景`、`打开项目…`。不展示左侧导航、工作步骤、产品功能介绍或再次解释保存与导出。

不为了填满窗口增加内容。未来有真实最近项目时，在这三个入口下增加紧凑列表，展示项目名、类型和可辨认的路径；没有记录时省略整块区域。最近项目不是第一阶段瘦身的前置条件。

原生窗口已经承担应用身份时，页面内不重复放大品牌；Web 模式可保留小型身份标识。

### 4.2 工作区：画布立即可操作

进入项目后地图与三维视图就是工作内容。空业务图层不等于没有工作区；有底图的画布不应该显示欢迎内容。

图层树空状态只保留“暂无图层”和“添加数据”，不再解释如何排序和分组。三维空对象树采用相同规则。加载进度、服务失败和重试按实际状态呈现，与空状态分开。

添加数据可以同时存在于高频工具区和空图层树，因为两处服务不同操作位置；无需在画布中央再增加第三个入口。

### 4.3 顶部：按任务分组，分组本身不再占文字

第一阶段保留现有任务分类，移除各分类下方可见的分组标题。这些标题不是命令，对操作没有额外作用。

第二阶段统一二维和三维顶部的布局组件。第一行放项目上下文、任务分类、保存／撤销／重做／更多；第二行放当前任务命令，支持收起。低频菜单保持可发现，快捷键保持有效。无需新增一条专门介绍应用或当前区域的品牌行。

常用命令保持固定顺序。空间不足时将低频操作收入更多菜单，或采用受控的单行滚动；不通过大量缩字、换行或只剩陌生图标维持所有按钮常驻。

### 4.4 属性表：工具和状态各一行，主要空间留给数据

默认结构如下，图中的符号仅表达位置；最终按钮应有可访问名称和必要提示：

```text
[points ▾]  [搜索…]  [仅选中]  [过滤]  [统计]  [选择 ▾]        [收起]
──────────────────────────────────────────────────────────────────
选择列  | ID        | name             | value
        | …         | …                | …
──────────────────────────────────────────────────────────────────
显示 3 / 12 · 选中 1 · 只读                   [‹] 1 / 1 [›] [100/页]
```

- 删除独立的“属性表”标题行。当前图层选择器同时承担上下文和切换入口；`aria-label` 保留“属性表面板”，不影响读屏识别。
- 搜索、过滤、选择操作与收起入口在一行。宽度不足时先折叠低频选择操作和统计入口，优先保留图层与搜索。
- 总数、当前显示数、选中数和分页共用底栏。无过滤／搜索／仅选中限制时显示“12 条”；有显示范围限制时显示“显示 3 / 12”，不能模糊搜索与地图过滤的范围。
- 过滤器、字段统计仅在打开后增加参数区；关闭后释放空间。活动过滤有小标记和清除入口，不靠永久介绍段落解释。
- 0 条结果仍保留统计底栏，分页置为不可用或省略；空结果本身显示“无匹配记录”和清除限制的入口。
- “只读／编辑中”是实际状态，需要保留；“双击单元格编辑”是操作帮助，放在相应控件提示中。不要永久显示两类句子。
- 表格内滚动，顶部和底栏固定；更改停靠高度不改变目标图层、过滤、分页或选择。

这里节省空间的方式是合并结构，不是减少必要状态或把所有工具隐藏到菜单中。

### 4.5 添加数据：先获得文件，再要求用户作决定

默认本地导入页优先显示“选择文件”与紧凑拖入区。文件格式和坐标系细节在适用时出现：CSV 显示字段／坐标配置，DXF 缺失坐标系时要求明确选择，已有合法信息的 GeoJSON 不预先展开设置。

本地与服务两个数据来源可以用顶部切换，不必默认分配一整列导航；是否切换结构以服务表单实际宽度验收。三步标题不必在简单导入中始终出现；复杂流程需要时保留步骤和返回能力。

坐标系缺失、冲突、解析失败应有直接可见的原因和恢复方式。文件格式列表、轴顺序解释及 WGS84 转换规则放到按需说明，不推迟必须由用户作出的坐标系选择，也不偷偷猜测。

### 4.6 属性编辑：普通属性立即反馈，真实事务明确提交

有效的对象位置、旋转、缩放、显示和场景参数直接反馈；保留输入过程、焦点、验证和撤销，非法中间值不提交。渲染偏好不污染项目内容或撤销历史。

导入、空间处理、发布、写文件等会产生结果或成本的操作保留明确执行动作。多参数草稿的提交边界需要按实际任务定义；不能为了统一外观删除已有样式草稿保护。后续简单样式属性可以提供实时预览，但只有验证预览、提交和撤销语义后才能替换当前流程。

变换手柄同步对象位置／朝向与视图缩放；清晰度同时检查高 DPI、分辨率比例、抗锯齿、瓦片精度和原始资源。控件小并不意味着数据或模型显示质量可以降低。

### 4.7 样式、标注、图例与属性字段

简单颜色、透明度、字号、标注修改应及时预览；图例与预览身份一致。分类生成、分级生成、字段结构和复杂 JSON 采用明确事务，验证后才能提交。切换、取消、撤销和保存重开遵守同一规则，不因为删掉应用按钮就把草稿保护一并删掉。

图形属性用“字段名｜类型｜值｜移除”的紧凑列表；普通值同一行，JSON 展开编辑。分类与图例显示真实类别，不只用首项符号代表整层。只读构件属性优先可扫读和复制，不为了与可编辑表单统一而伪装成可输入字段。

### 4.8 服务连接与数据目录

默认显示 URL、类型、必要认证与连接动作；目录以名称与选择为主体。选中条目才展开适用的样式、格式或矩阵集，长 CRS／范围／版本进入详情。

直接显示只读、完整／截断、当前范围、要素上限、不兼容原因和认证保存方式。TileMatrix 实现、分页机制、WFS-T 等长说明进入帮助。连接、添加、加载、刷新是不同阶段，失败时保留可以继续的参数或旧快照。

### 4.9 空间处理与结果

公共结构为“当前工具＋帮助、输入与范围、工具参数、输出、运行状态”。工具名称出现一次；参数标签和值同行；结果与计算说明按需展开。顶点质心等与常见预期不同的工具用准确名称，不靠常驻教程修补歧义。

输入数量、第二输入、单位、连接关系、输出字段／范围和执行动作可直接读到。运行提供取消，失败提供原因，成功提供查看结果；参数变动后旧结果必须标明为上次运行，预览过期时清除。几何问题使用紧凑报告表，选择与定位共用工具区。

工具不适用时指出缺少哪类图层并给恢复入口。支持的 18 个工具全部验收，无参数的简单工具也不能显示空的“参数”分组来凑结构。

### 4.10 三维树、绘制、对象组织与资源

对象树默认一行名称＋显隐／类型图标／异常状态／更多，加载或失败时允许显示附加信息。多选教学和拖放提示按操作出现，不永久分配底栏与空白拖入区。分组继承状态、混合值、锁定原因是工作状态，需要清楚保留。

普通改名行内 Enter 确认、Esc 恢复；批量删除明确对象数量，解散分组明确保留成员。绘制与顶点编辑保留短操作条，因为用户正执行一个需要完成／取消的任务；坐标预览和最终几何提交不要混为已保存。

资源添加／更新保留 URL 校验和明确请求边界；原始坐标数组不是默认编辑界面。手柄、字段与模型变化必须同步，预览退出恢复原有面板布局；模型加载错误在对应对象处可重试。

### 4.11 导出、文件与发布

导出以目标、范围／数量、格式和动作组成紧凑表单。复杂格式参数在选中后出现；坐标系、单位和输出损失直接表达，快照实现及长说明进入 info／详情。复制为本地图层使用复制的词汇。

明确区分项目保存、数据导出、三维场景／对象导出与静态发布。浏览器下载已发起不等于文件已写入磁盘；原生取消或写入失败不改变当前项目。宿主支持与缺口必须用实际流程验收。

静态发布向导是后续独立能力。当前已有 CLI 发布器，未接入桌面 UI；不能把只导出 scene.json 描述为完成资源打包和部署。

### 4.12 Viewer 与帮助

Viewer 是查看产品，默认让地图／场景占主要空间，使用小型场景身份、可收起图层／图例、按需属性弹窗。删除 MAP SCENE 等装饰性介绍层；尊重场景 widgets、分类图例、分组实际显隐和主题语义。

整体加载失败和部分资源失败分开；提供重试、错误详情和可继续查看的内容。窄屏辅助面板按需出现，不把图例隐藏后彻底失去入口。移动查看另有验收，不直接套用桌面编辑器的密度。

帮助承接必要操作说明、快捷键和参数知识，关于呈现真实版本信息。普通 tooltip 简短且支持焦点；较长内容使用可点击说明，不依赖一个固定尺寸、瞬时消失的小浮层。

## 7. 验收方法与当前测试缺口

“测试通过”需要区分算法、功能流程、产品体验三类结果。`8e596a7` 的功能检查通过，但本次截图证明它仍有设计缺陷。

1. **进入工作区**：分别新建和打开二维／三维项目，覆盖无业务数据但底图可用的状态；移动地图后仍无中央引导。删除最后一层也不重新显示欢迎内容。
2. **属性表**：多图层切换浏览不改变表的绑定；搜索、地图过滤、仅选中、零结果、分页组合均显示正确状态；面板缩小和恢复不丢输入、页码或滚动位置。
3. **编辑**：保持编辑目标锁定；实时属性、非法输入、撤销和保存重开一致；多参数草稿不会被布局调整或切换对象静默丢弃。
4. **导入**：GeoJSON 正常文件、坐标系缺失的 DXF、需配置的 CSV，以及无效文件均从可见界面走完整路径；取消和返回后可继续。
5. **视觉与可访问性**：检查上述尺寸目标；同时检查文字、焦点、提示和点击区域。截取起始页、空工作区、导入、属性表、属性检查器，并实际检查截图。
6. **原生与浏览器分开**：浏览器可以验证布局和业务路径，文件对话框、系统缩放、原生窗口行为及远程三维数据仍需单独确认，不以浏览器结果代替。

现有 `workbench.e2e.ts:43–47` 要求地图区域中央的“添加数据”按钮可见，应在 A 批改为“不存在中央引导、工具入口可用”。当前浏览器测试阻断 OSM 瓦片；这适合隔离网络的功能回归，但还需要实际可用底图的人工检查来发现真实地图上内容遮挡和对比度问题。

上面的六项是基础检查；完整范围使用[全量审计 T01–T12](product-interface-audit-2026-10-08.md#5-全产品验收任务)。特别补齐服务故障、全部 18 个处理工具、三维字段／材质／组织、原生退出与文件、发布 Viewer，以及每个界面的无目标／零结果／忙碌／失败状态。

每批证据记录当前 SHA、宿主、窗口／DPI、数据与实际结果。源码确认不替代人工验收；浏览器验证不替代原生验证；成功默认态截图不替代错误和恢复路径。文档更新本身不需要重跑构建，但进入运行时代码实施后须运行匹配范围的测试和构建。
