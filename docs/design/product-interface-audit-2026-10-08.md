# WebGIS 全量界面设计审计

日期：2026-10-08。源码基线：`8e596a7`。配套文件：[产品设计原则与实施计划](product-design-review-2026-10-08.md)。

## 1. 范围与证据

本次从 `App`、二维 `Workspace`、三维 `CityWorkspace` 和 `apps/viewer` 的入口追踪当前可达界面，按用户任务拆为 **51 个界面／功能区**。这不是 51 个独立页面；同一组件中的筛选、统计、编辑等不同任务分别审计。

审计包括布局、信息层级、文字职责、目标对象、提交边界、状态恢复、错误反馈、键盘操作和宿主差异。源码能够确认渲染结构和事件行为，不能替代运行时尺寸测量或完整交互验收。

证据标记：

- **C**：已检查当前源码；表中注明对应文件。表内路径相对于 `apps/desktop/src/`，Viewer 路径另列。
- **S**：还有用户截图证据；截图可能是此前版本，不能据此认定当前默认状态。
- **V**：后续需要实际操作验证；包含需要构造数据、远程服务或原生窗口的状态。

本轮完成全量源码审计并复核已有截图，没有逐一打开所有弹窗，没有重新操作 My3dtiles，也没有重新完成原生 Tauri 验收。尺寸、焦点丢失和窗口关闭等运行时风险均作为待验证项，不能标记为已经修复或已经复现。附带交接材料提供背景，不自动成为本轮新的实施指令。

排除当前未接入入口的旧 `HeaderContent`／`HeaderTabs`／`HeaderGroup`／`HeaderButton` 组合，以及开发示例、测试夹具、构建产物和 Cesium 内部调试界面。旧组件保留情况属于维护问题，不能当作用户当前看到的界面。`CityMenu` 多数分支也不属于当前三维工作区的主入口，应以 `CityRibbon`、项目菜单和对象菜单为准。

发布器当前提供 CLI 能力；**桌面发布向导尚不存在**。它记录为后续能力缺口，不虚构已有发布页面。本次同时审计发布物的 Viewer，因为它直接面向最终使用者。

## 4. 共同交互契约

### 4.1 文字与层级

每段文字必须有一种职责：**命名、真实状态、必要决策、错误恢复、辅助帮助**。前三种压缩后仍可见，最后一种按需。删除没有任务作用的重复介绍。单位、坐标参考、数据完整性、输入／输出范围不能转移到只靠悬停才能发现的位置。

一个区域最多一个身份层。检查器已有目标选择和标签时不再叠加“概览／属性／对象名称”大标题；表已有图层选择器时不再单独加“属性表”。真正复杂的参数仍可以分组，但组标题不机械地出现在每个单字段上。

### 4.2 修改如何生效

| 操作 | 用户看到的反馈 | 提交与撤销 |
| --- | --- | --- |
| 名称、位置、颜色、透明度、字号、场景普通参数 | 有效值及时反馈；输入中间态保留；非法值在字段旁纠正 | 一次明确编辑合理合并，支持撤销；不要求再点通用应用按钮 |
| 拖动变换、连续滑块 | 连续预览 | 松开或完成手势提交一次；Esc 恢复；不因每帧更新产生历史条目 |
| 样式分类／分级生成、过滤条件组、顶点重构、弹窗字段结构、JSON | 明确草稿／预览身份，可比较结果 | 定义事务确认与取消；切换／关面板不静默丢失；预览不是已保存 |
| 服务地址、资源地址、认证变更 | 先校验，再显示连接／加载状态 | 不对每个键重新联网；按 Enter／离开字段等确定有效值或明确更新命令触发 |
| 导入、计算、导出、发布 | 明确动作、进度、取消、结果与失败原因 | 保留执行按钮；成功才写入结果；取消不提交部分项目变化 |
| 面板、密度、本机画质 | 修改立即可见 | 本机偏好，不触发 Project Dirty 或 Undo；项目环境设置按项目保存 |

这些是目标契约，当前实现不全部满足。优先使用已有命令、`LivePropertyInput` 和会话状态；不为表单瘦身提前引入一套通用事务框架。

### 4.3 状态与恢复

| 状态 | 呈现原则 | 恢复动作 |
| --- | --- | --- |
| 没有业务数据 | 所属树或数据区域一条轻量状态；可用画布保持可操作 | 添加数据／资源 |
| 搜索或筛选零结果 | 明确哪个范围没有结果 | 清除对应限制，保留其他范围 |
| 未绑定目标／不适用 | 说明当前缺少什么对象或能力 | 选择目标、复制只读快照；不把控件无理由置灰 |
| 部分资源失败／快照不完整 | 对象行／目录／属性就近显示；避免全局白屏 | 重试、改地址、保留旧快照、查看原因 |
| 正在运行 | 当前动作、可用进度、取消；不要编造百分比 | 取消后回到可继续的输入状态 |
| 未保存／未应用草稿 | 在唯一权威上下文显示状态 | 保存、提交／取消；保护范围明确 |
| 长名称／长路径／长字段 | 常态截断或换行，完整值可复制查看 | 焦点／详情入口；不能只靠鼠标 title |
| 窗口缩小或 DPI 增大 | 优先保留任务主体，低频工具进更多；按需要重排 | 可恢复面板，主要动作不出屏 |

## 6. 后续如何避免再次漏审

新增界面先归入此清单的任务域，写清目标对象、提交边界和相关状态；若没有归属，补充一行清单。进入实施后每个批次更新问题状态为“待实施／实施中／已验证”，已验证必须附版本和证据，不能用本文的目标描述证明完成。

设计验收与功能测试并列：布局占用、重复文字、目标语义、焦点／恢复四类结果都要检查。参考产品和视觉 skill 只提供方法，不能覆盖用户的紧凑专业工具要求；不为了“高级感”增加营销文案、巨型留白、动效或装饰浮卡。

当前旧 V0.1 规范仍含 Vue 技术栈描述、较早的顶部与默认面板图；统一工作台文档又有后续覆盖段落。后续应整理为一份现行规则和历史记录，消除相互冲突的入口。本审计属于最新设计提案，运行行为仍以当前代码为准。
