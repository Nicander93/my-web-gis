# Desktop WebGIS UI/UX 设计与组件规范

> 版本：Implementation Baseline 1.0 · 2026-10-13  
> 唯一最终视觉参考：`../prototypes/workbench/desktop-webgis-2d-final.html` 和 `desktop-webgis-3d-final.html`  
> 适用：React 加 Tauri 的桌面端；覆盖独立的二维和三维项目

## 1. 产品观感与信息密度

定位是成熟的桌面 GIS 工具，参考 QGIS 对专业信息的组织方式、窗口管理方式和 GIS 工具的操作逻辑。要求**安静、紧凑、内容优先，需要时能承载密集的专业信息**。不能把所有属性、所有工具、所有状态卡片同时铺在界面上，也不能把生产工具做成营销用的 Dashboard。

- 浅色中性背景，克制的绿色作强调色。手绘或拟人风格只用在 Logo、空状态和插图上；**工具图标和参数表单必须规整精准**。
- 业务状态的层次是：应用框架 < 用户当前操作 < 地图和数据。地图永远是面积最大的工作区域。
- 预设颜色参考**两份 HTML 里的 CSS 变量**，不要另外发明第二套视觉主题。例如三维用 `--paper:#fafbf9`、`--line:#dfe4e2`、`--accent:#2f695b`，二维用 `--bg:#f7f9f6`、`--green:#346e55` 作为近似基准；实现时把含义相同的颜色收敛成一套 Design Token。
- 中文优先，英文 API 名称要能搜到；优先使用系统字体和稳定的 UI 字体回退，不要求所有用户安装定制字体。数字、坐标和单位在输入框和表格里等宽对齐。

## 2. 原型与代码实现的边界

HTML 里内嵌的 SVG 地图、演示 POI、模拟数据和弹窗只用于展示 **UI 结构和交互样例**。正式实现必须复用真实的 OpenLayers 或 Cesium 渲染器、项目命令和文件服务。Agent 不能照搬模拟的 `toast('成功')` 来替代真实操作。

优先复现的是空间布局、窗口层级、工具密度、面板操作、属性区块、状态反馈和快捷键语义。示意地图的配色和演示图层的名称不属于真实数据的要求。

## 3. 统一结构

```text
Desktop App
├── Application Menu (1 row): 文件 / 窗口 / 设置 / 帮助
├── Ribbon Tabs (1 row): 按项目类型切换
├── Ribbon Tools (1 row): 紧凑图标 / 工具组 / 下拉
├── Workspace Overlay Root (full bounds)
│   ├── GIS Canvas (absolute, full width & height)
│   ├── Docking Windows (left/right/bottom/floating)
│   ├── Context Menus / Tool Hints / Nonmodal Editors
│   └── Temporary drawing handles / measurement overlays
└── Status Bar
```

**不可协商的布局规则：**

1. **画布占据 Workspace 的全部范围**，不能给左右面板预留真实的空白宽度；GIS 鼠标坐标仍然按原始 Canvas 的实际尺寸解析。
2. 左右面板默认覆盖在画布上；浮动窗口可以移动和调整尺寸；打开操作窗口不应触发地图 resize 或相机重新取景。地图被窗口覆盖是允许的。
3. `flyTo` 和定位的目标点是**整个视口的几何中心**。禁止根据面板边界人为加偏移。
4. 属性表停在底部时横跨 Workspace 的 100% 宽度，可以浮动或最大化。左右面板和底部面板互相遮挡时，要有明确的层级和焦点优先级，确保能够拖动和关闭，关键控件不会被隐藏。
5. 默认只打开左侧的树；右侧检查器、底部属性表、工具箱、日志和性能诊断都关闭；不保留边缘常驻的恢复条或隐藏的胶囊按钮。需要时通过`窗口`菜单打开。
6. 顶部应用菜单、Ribbon Tab 和 Ribbon 工具严格保持三行，不叠加第四行的“命令导航”或常驻的指令横幅。
7. 焦点模式只关闭浮层，不销毁状态；退出后原样恢复布局。布局保存在本机，跨项目时不会破坏用户的习惯。

## 4. Window Manager 的行为约定

| 能力 | 行为与约束 |
|---|---|
| 打开与关闭 | `窗口`菜单用勾选态表示；关闭后完全从可交互区域消失，再次打开时恢复到合理位置 |
| 停靠 | 左、右、底三个位置；不能落在屏幕外的不可访问区域；支持从浮动转为停靠、从停靠转为浮动 |
| 浮动 | 有完整的标题栏，可以拖动、调整尺寸和关闭；始终高于地图，但不必加模态遮罩 |
| Z 顺序 | 单击或拖动激活某个窗口后它置于最前；不同浮动窗口的焦点要明确，Esc 发给当前活动的工具或窗口 |
| 定位持久化 | 独立于项目，由布局服务管理；屏幕分辨率变化后，位置会 clamp 到可见范围内 |
| 属性窗口 | 与对象 ID 固定绑定；场景里的选择变化不会偷换编辑对象；支持 Apply/OK/Cancel |
| 模态限制 | 文件覆盖、严重验证这类需要确认的事务操作可以模态；一般的属性、分析和裁剪参数优先用非模态 |
| 无障碍 | 菜单和窗体都能用键盘到达；除了拖动，还要提供关闭和停靠的菜单项；只在真正的模态弹窗里使用 focus trap |

在技术选型上，优先选择成熟且能满足上述行为的 Docking 库（需要验证对 React 19 的支持、布局保存与恢复、窗口叠层以及许可证）；不要为了用第三方库而牺牲“地图不缩放”这条约束。通用窗口可以用成熟的 React 控件，复杂的 GIS 图形控件自己实现。

## 5. Ribbon 和工具状态

- 二维 Tab：**地图 / 编辑 / 数据 / 分析**。
- 三维 Tab：**场景 / 标绘 / 编辑 / 瓦片 / 分析**。
- Tab 下面是单行工具组，主操作一眼可见，低频工具放进 Dropdown 或更多。图标统一用 Lucide 或同级别的单线图标，标签要短且明确。
- 一个工具可以处于：`available`、`disabled(reason)`、`active`、`busy(progress)`、`error`。点击处于 disabled 的工具，要说明可理解的原因，不能静默失败。
- 依赖上下文的操作，例如`压平`，只在选中可编辑的 Tileset 时启用；`移动轴`只对模型和目标 Tileset 可用；`编辑顶点`只对适用的 Graphic 和矢量可用。
- Ribbon 上的取消和选择工具始终可以访问；Esc 的行为见产品规范；绘制过程中只用紧凑的工具提示，不要把操作教学铺满整个屏幕。
- 生产环境的 Ribbon 里不展示没有运行时实现的“模拟裁剪”“运行分析”按钮；如果产品路线需要保留未上线的入口，要明确标记为不可用。

## 6. 场景树、图层树和右键菜单

树节点紧凑展示：显隐眼睛、展开状态、图标、名称、加载错误或锁定信息、右键更多。文件夹和对象可以混排，不强制系统级的点线面分类。

- 文件夹支持多级嵌套、任意节点拖放、跨父目录移动和排序。拖放目标要高亮；非法的拖放有明确反馈；禁止形成循环的父子关系。
- 单击选择，不强制滚动；双击定位；右键菜单会检查操作能力，并显示完整的属性入口。
- 节点自身的显隐是独立状态；父文件夹的可见和锁定参与**有效状态**的计算，但不改写子对象自己的显隐和锁定值。
- 搜索时可以看到命中的深层对象及其父路径，并允许`在树中定位`；搜索结束后保留用户原先的展开状态。
- 树的项数超过数百项时，引入虚拟列表、增量渲染或按需展开。独立的 POI 不需要转换成数据图层。
- Tileset 的 Feature 元数据使用检查器的拾取视图，不能为它们创建上百万个树节点。

## 7. 检查器与完整属性窗口

**检查器**用于快速编辑当前选择，只有已经打开时才响应选择变化，可以固定到某个对象；没有选择时展示简洁的空态。不属于当前对象类型的字段不能占位显示。

**完整属性**是一个独立窗口。推荐两列布局：左侧是可搜索的分类导航，右侧是密集的专业表单；主动作区在底部，放`应用 / 确定 / 取消`。窗口固定对象 ID，草稿有未应用状态，输入要验证，效果可以实时预览并在取消时回滚。

### 7.1 分类建议

| 对象 | 属性分类 |
|---|---|
| 二维矢量图层 | 常规、源与 CRS、符号化、标注、字段、过滤、渲染、元数据 |
| 二维要素 | 常规、业务字段、几何、编辑历史与辅助信息 |
| 3D Tiles | 常规、资源、显示与样式、LOD 与缓存、裁剪与压平、位置与变换、拾取元数据、诊断 |
| GLB | 常规、资源、显示与材质、动画（有时）、变换、交互、元数据 |
| POI 或图标点 | 常规、图标、文字、距离与可见条件、交互与弹窗、位置、业务属性 |
| 线面 Graphic | 常规、线型与材质、面填充与轮廓、几何点、高度模式、交互、业务属性 |
| Folder | 名称、可见与锁定、组织信息；**没有图层样式编辑** |

Cesium 的原生字段（如 `maximumScreenSpaceError`、`scaleByDistance`、`heightReference`、`distanceDisplayCondition`）保留英文 alias 供搜索，同时显示可读的中文名、取值范围和单位，以及警告或帮助。软件自定义的扩展字段另行标识。

### 7.2 表单规则

- 严格区分设置中的草稿值、预览值和已应用值。`Apply` 可以连续提交且不关闭窗口，`OK` 提交后关闭，`Cancel` 回滚**尚未应用**的更改。
- 数值的单位、默认值、边界条件和精度要明确，不能输入 NaN 或 Infinity；颜色、符号和可见性的实时预览要能回滚。
- 在树上切换选中对象，不会改变已经打开的属性窗口所编辑的目标。
- 位置、经纬度、旋转和缩放集中在同一个专业分类里，不占用所有属性页面的主要空间。Gizmo 和数值编辑交替使用，不要求输入和拖拽时每帧同步，但最终结果必须一致。

## 8. 属性表、工具箱、参数窗

### 属性表

- 底部占满宽度的一个 Tab 容器，支持多个数据集，可打开、关闭、浮动和最大化。
- 上方只放紧凑的工具栏：筛选、搜索、只看选中、统计、编辑开关、更多字段操作。
- 可读和可编辑的状态要有明显区分。输入的合法性、类型转换、批量应用与撤销，以及执行进度都要清楚。
- 行选中只高亮地图，不自动缩放；双击行头定位；在编辑模式下双击单元格才进入编辑。
- 记录量很大时使用虚拟滚动或分页，并保留每个 Tab 的滚动位置、列宽、筛选和排序状态。

### 工具箱及结果

- 工具箱可以搜索，提供类别、参数概要和运行入口；运行处理算法时弹出非模态的任务窗口，展示参数、CRS 与单位、输出策略、进度与取消、错误和产物。
- 剖面这类包含多个数据点的结果，可以用可调整尺寸的图表窗口展示，结果和来源要清楚。

### 裁剪与压平

- 流程是：选择 Tileset → Ribbon 工具 → 绘制或指定范围 → 参数窗 → 预览 → 应用。
- 参数窗应显示目标对象的名称、保留内部还是外部、或目标高程、范围的编辑方式，以及启用状态；未完成时按 Esc 取消。
- 重新打开项目后配置列表仍然可见；选中目标 Tileset 后，可以在它完整属性的`裁剪与压平`页里统一管理。

## 9. 统一反馈与状态栏

- 状态栏保持统一的高度和视觉样式。二维显示 CRS、比例尺与分辨率、坐标、选中数量；三维显示坐标、相机高度与方向（适用时）、选中数量、渲染状态；两边都显示未保存状态、后台任务和错误入口。
- 命令完成的反馈要能核对：新建的图层节点或结果集、画面上的实际变化、可撤销的记录，不能只弹一个 toast。
- 异步操作有 `loading / success / error / cancel` 几个阶段；网络错误和资源丢失要能追溯到具体的图层或数据源。
- 诊断是独立的窗口，分性能、资源、调试三个 Tab；OpenLayers 静态时帧率显示为空闲；内存和显存取不到时显示“不可用”，估算值标注“估算”。

## 10. 尺寸、布局与视觉验收

下面是建议的初始范围，**原型里的实际效果优先**，数字可以根据真实的 UI 密度做小幅调整：

| 组件 | 建议 |
|---|---|
| 应用菜单行 | 32–38 px |
| Ribbon Tabs | 30–36 px |
| Ribbon 工具行 | 48–68 px（紧凑一行） |
| 状态栏 | 24–30 px |
| 左树首次宽度 | ~260 px |
| 检查器默认宽度 | ~310 px，默认关闭 |
| 属性表初始高度 | ~280–320 px，默认关闭 |
| 工具控件 | 30–34 px 高，密集表单可以更小，但要满足可点击区域 |

验收至少使用 **1366×768** 和 **1920×1080** 两种窗口尺寸，并分别检查 100% 和 125% Windows 缩放下的主布局；浮窗不能越过可访问的屏幕边界。验收时对最终原型做结构比对，而不是只比较截图里的色值。

## 11. UI 自动化用例（必测）

1. 新建二维项目：左树打开，其它关闭；打开属性表，验证它横跨 Workspace；地图底图的有效视口不改变。
2. 二维图层右键“属性”打开浮动窗口，修改样式后 Apply，图层随之改变；按 Cancel 时未应用的草稿不改变任何内容。
3. 在图层树里选中图层，再单击属性表的某一行，只有地图高亮；双击行头才定位。
4. 调整、拖动、关闭左右和底部窗口，重启后布局仍在；重置布局后恢复为左树打开、右侧和底部关闭。
5. 新建三维项目，选择图标点，连续点击生成三个独立的 Graphic，按 Esc 退出后再点击不会新增对象。
6. 选中一个独立的 POI，右键打开属性，修改图标或大小，只更新当前对象，不影响相邻的 POI。
7. 对 3D Tiles 做裁剪，未应用时按 Esc，不留下临时控制柄，也不改变已有的效果。
8. 同时打开性能诊断和属性浮窗，拖动其中一个，不改变 Cesium viewer 画布尺寸，也不改变定位中心。
9. 键盘焦点在数值输入框或属性表单元格里时，按方向键和 Backspace 不触发地图工具的快捷键。
10. 在小屏上打开布局时，所有窗口的标题栏和关闭操作仍然可达。

## 12. 反模式（设计禁区）

- 把生产软件做成大号按钮卡片、全屏 Dashboard、常驻帮助提示，或“工具展示墙”。
- 靠压缩地图宽度来伪造 Docking；或为了避让面板而修改定位点的中心。
- 把属性检查器做成只有四个概览字段的 Demo；或把所有专业字段不加分类地同时铺开。
- 给每个 POI 都在树里自动创建一个 GraphicLayer，或者强制按点、线、面分文件夹。
- 截断复杂字段、隐藏保存失败、伪造进度、伪造测量结果、伪造压平截图。
- 强制覆盖用户自己的窗口布局，或在更换项目后丢失焦点和面板浮动状态。
